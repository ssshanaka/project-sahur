# Layer 1: The Data Pipeline

Everything starts with data. As the saying goes in AI engineering: **Garbage in, garbage out.**

```text
Raw Chat Logs / Prompts ──► [ Cleaning & Balance Script ] ──► datasets/sahur_genz_v1.jsonl
```

### What happens in Layer 1?
1. **Gathering**: We collect conversation pairs, Gen Z slang dictionaries, humorous exchanges, and instruction-following examples.
2. **Cleaning & Formatting**: We strip duplicate entries, clean broken formatting, and convert all data into standard OpenAI/Hugging Face ChatML format:

```json
{
  "messages": [
    {"role": "system", "content": "You are Sahur, a hyper-responsive Gen Z AI assistant who speaks naturally with humor."},
    {"role": "user", "content": "Can you explain how attention mechanisms work?"},
    {"role": "assistant", "content": "No cap, attention is basically the model playing favorites with words..."}
  ]
}
```

---

# Layer 2: Base Model Integration

Instead of spending $10M pretraining a model from scratch, we load a high-performing open-weight base model.

```text
Hugging Face Hub ──► [ download_model.py ] ──► models/Qwen3-0.6B/
```

### Why Qwen3-0.6B?
- **Lightweight**: ~600 Million parameters.
- **Fast**: High tokens-per-second even on consumer GPUs and CPUs.
- **Modern**: Uses Rotary Positional Embeddings (RoPE), SwiGLU activations, and Grouped-Query Attention (GQA).
- **VRAM Friendly**: Requires under 1.5 GB VRAM for inference and under 4 GB VRAM for QLoRA training.

---

# Layer 3: QLoRA Fine-Tuning & Alignment

This is where the magic happens. We train **Sahur v0.1**.

```text
Qwen3-0.6B + sahur_genz_v1.jsonl ──► [ Unsloth / QLoRA Trainer ] ──► checkpoints/sahur-lora-v1/
```

### The Hybrid Cloud + Local Workflow
Because training models requires fast GPU VRAM:

- **Google Colab (Free T4/A100 GPU)**: Used to run heavy training epochs.
- **Local VS Code**: Used to write scripts, manage Git, inspect datasets, and write documentation.

```text
┌─────────────────────────────────┐        ┌─────────────────────────────────┐
│       LOCAL LAPTOP WORKSPACE    │        │       GOOGLE COLAB (GPU)        │
│  - Code & Documentation         │        │  - Run Unsloth / TRL Trainer    │
│  - Data Cleaning Scripts        │ ─────► │  - High-Speed VRAM Training     │
│  - Git Repository Management    │ ◄───── │  - Save Checkpoints to Hub/Drive│
└─────────────────────────────────┘        └─────────────────────────────────┘
```

During training, we use **QLoRA (Quantized Low-Rank Adaptation)**:
1. The base model weights (`Qwen3-0.6B`) are frozen in 4-bit precision.
2. Small trainable matrix adapters (LoRA) are attached to key Attention and Feed-Forward layers.
3. Only the adapter weights (< 10 MB) are updated during gradient descent!

---

# Layer 4: Export, Quantization & Local Deployment

Once training completes, we ship the final artifact so anyone can run it locally on their laptop without internet access or GPU dependencies.

```text
[ Base Model + LoRA Adapter ] ──► Merge ──► [ llama.cpp Export ] ──► exports/sahur-v0.1-Q4_K_M.gguf
                                                                              │
                                                                              ▼
                                                                     [ Ollama / Open WebUI ]
```

### Step-by-Step Export Flow:
1. **Merge**: We fuse the LoRA adapter weights back into the main Qwen3 base model to create a standalone model checkpoint.
2. **Convert & Quantize**: We use `llama.cpp` to convert the model into **GGUF format** at `Q4_K_M` (4-bit quantization).
3. **Local Deployment**: We load the `.gguf` file into **Ollama** or **vLLM**, allowing you to chat with Sahur locally via terminal or a sleek desktop UI (**Open WebUI**).
