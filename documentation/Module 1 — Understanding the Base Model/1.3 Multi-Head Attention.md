# Module 1.3 — Multi-Head Attention

## How LLMs learn multiple things at the same time

Welcome to the lesson where most people have their first **"Wait... that's actually genius."** moment.

Last lesson, we learned that **Attention** lets a word decide which other words are important.

Today you'll learn something even cooler.

> **A Transformer doesn't have ONE attention mechanism.**
>
> It has **many**, all working at the same time.

This is called **Multi-Head Attention (MHA).**

# The Full Pipeline

Here's what actually happens inside one Multi-Head Attention layer.

```text
Input Embeddings
        │
        ▼
Create Queries, Keys, Values
        │
        ▼
Split into Multiple Heads
        │
        ▼
Head 1 → Attention
Head 2 → Attention
Head 3 → Attention
...
Head N → Attention
        │
        ▼
Concatenate Results
        │
        ▼
Linear Projection
        │
        ▼
Output
```

Every head processes the **same input**, but each one uses different learned weight matrices.

# Do Heads Actually Specialize?

Researchers have visualized attention heads.

Some heads consistently learn things like:

- Matching quotation marks
- Matching brackets
- Subject ↔ verb agreement
- Pronoun resolution
- Indentation in code
- Long-distance dependencies
- Repeated phrases

Not every head has a clean job, but many develop recognizable patterns.

# Where does LoRA fit?

This is the first glimpse of something we'll study deeply in Module 7.

Inside Multi-Head Attention are linear layers that produce the Queries, Keys, Values, and output projection.

Conceptually:

```text
Input

↓

Linear Layer

↓

Queries
```

LoRA doesn't replace the whole layer.

Instead it learns a **small adjustment** to that layer.

You can think of it like this:

```text
Original Layer

+

Tiny Adapter

=

Improved Layer
```

So instead of retraining hundreds of millions of parameters, we only train a tiny fraction of them.

That's why LoRA is so memory-efficient.

# One Important Misconception

Many people think:

> "One head learns coding."

Not exactly.

A head isn't assigned a profession.

It learns whatever patterns reduce prediction error during training.

Sometimes that's punctuation.

Sometimes syntax.

Sometimes long-range context.

Sometimes multiple things.

It's an emergent behavior, not a hardcoded role.

# ⏭ Next Lesson — Module 1.4: Feed Forward Networks (FFN)

You've now seen **how the model gathers information** (Attention).

Next, we'll learn **how it actually thinks with that information**.

Many people assume Attention is the "brain" of a Transformer. It isn't.

Attention gathers context.

The **Feed Forward Network** performs most of the heavy computation that transforms those contextual representations into richer, more useful features. Once you understand FFNs, you'll know why they account for such a large portion of a model's parameters—and why they're another major target for efficient fine-tuning methods like LoRA.
