# The Simple Structure

An FFN is surprisingly simple.

```text
Input

↓

Linear Layer

↓

Activation Function

↓

Linear Layer

↓

Output
```

That's it.

No magic.

---

# Why Two Linear Layers?

Imagine you're editing a photo.

Step 1

Increase brightness.

Step 2

Increase contrast.

The second step only makes sense after the first.

Same idea.

The first layer expands information.

The second compresses it back.

---

# Expansion

This is genius.

Suppose the hidden size is

```text
1024
```

The FFN expands it.

```text
1024

↓

4096
```

Now the model has much more "thinking space."

Then

```text
4096

↓

1024
```

Compress it back.

Why?

Because it's easier to discover complex patterns in a larger feature space.

---

# Visualizing It

Imagine inflating a balloon.

```text
Small

↓

Big

↓

Small
```

While the balloon is large...

You can draw much more detail.

Then you shrink it again.

That's essentially what the FFN does with vectors.

---

# Activation Function

Without an activation function...

The FFN would basically become one big linear transformation.

That would severely limit what it can learn.

Activation introduces non-linearity.

Think of it like this.

Without activation

```text
Straight Line
```

With activation

```text
Curves

Corners

Patterns

Complex Relationships
```

Modern LLMs often use activation functions like **SiLU** (also called Swish) or **GELU**, depending on the architecture.

# Where are Most Parameters?

Here's something that surprises many people.

People think

↓

Most parameters.

Actually...

In many Transformer models,

the **Feed Forward Networks contain the largest share of the parameters**.

Why?

Because of those huge expansion layers.

Example

```text
1024

↓

4096

↓

1024
```

Those matrix multiplications are enormous.

# Attention vs FFN

Let's compare.

| Attention            | FFN                          |
| -------------------- | ---------------------------- |
| Collects information | Processes information        |
| Connects tokens      | Works on one token at a time |
| Finds relationships  | Learns features              |
| Communication        | Computation                  |

Think of them as teammates.

Attention asks

> "Who should I listen to?"

FFN asks

> "Now that I've listened... what does it mean?"

---

# Real Example

Prompt

> "Write a Python function that reverses a string."

Attention figures out:

- This is about Python.
- "reverse" relates to strings.
- The request is to generate code.

The FFN transforms those contextual representations into features that help predict:

```python
def reverse_string(text):
    return text[::-1]
```

It doesn't "store" that function as a template—it computes representations that make those next tokens highly probable.

# One Common Misconception

People often say:

> "Attention is all you need."

That's actually the **title of the original paper**, not a claim that FFNs are unimportant.

The Transformer architecture introduced Attention as the key innovation over earlier sequence models, but every Transformer block still contains Feed Forward Networks, normalization layers, residual connections, and other components.

Without FFNs, today's LLMs wouldn't work nearly as well.
