# Spaces Matter

Even spaces are important.

Example

```text

```

can be one token.

But

```text

```

(with a leading space)

Modern tokenizers often encode leading spaces because they're extremely common in natural text.

# Why This Matters

Suppose

Model A

```text
20 tokens
```

Model B

```text
13 tokens
```

Same sentence.

Who is faster?

Model B.

Because Transformers process tokens—not characters or words.

Fewer tokens generally mean:

- lower latency
- lower memory usage
- fewer computations

# Why Does OpenAI Feel Fast?

One reason is excellent tokenizer design.

If common text compresses into fewer tokens,

the model has less work.

Of course, inference optimizations and hardware also play major roles.

# Why Can't We Easily Change the Tokenizer?

This is HUGE.

Imagine your tokenizer says

```text
Hello

↓

9707
```

The model learned

9707

for years.

Now you suddenly change it.

```text
Hello

↓

551
```

Everything breaks.

The embeddings no longer match the token IDs.

The model has effectively learned a different language.

Changing the tokenizer after pretraining usually requires retraining or extensive adaptation, which is why most fine-tuned models keep the original tokenizer.

# Can We Build Our Own Tokenizer?

Yes.

Researchers do it.

But...

You'd usually do this when **pretraining a brand-new model from scratch**, not when fine-tuning an existing one.

If we replaced Qwen3's tokenizer today,

we'd also need to adapt or retrain the embedding layer, and performance would likely suffer without a large-scale training effort.

For Project Sahur, keeping Qwen3's tokenizer is absolutely the right choice.

# One Common Misconception

People often say:

> "The model knows English."

Not really.

The model knows patterns over sequences of **token IDs**.

English, Python, HTML, emojis, and even code all become the same thing internally:

Numbers.

That's why the same architecture can learn so many different domains.

---

# Why This Matters for Project Sahur

Since we want Project Sahur to be:

- fast
- lightweight
- conversational
- local-first

understanding tokenization helps us make smarter decisions.

For example:

- If our training data uses lots of repeated slang or formatting that tokenizes efficiently, that's great.
- If we create prompts that explode into unnecessary tokens, we'll waste context window and inference time.

Optimizing prompts and datasets isn't just about wording—it's also about how the tokenizer sees them.
