Suppose you type

```text
pizza
```

The tokenizer says

```text
pizza

↓

Token ID = 48271
```

Now ask yourself...

Can the Transformer do math using

```text
48271
```

No.

It's just an integer.

The model needs something much richer.

---

# Enter Embeddings

Instead of

```text
48271
```

The model converts it into

```text
[-0.21,
0.73,
-1.45,
0.82,
...
1024 values]
```

This is called an **embedding vector**.

The Transformer understands vectors.

Not IDs.

---

# The Embedding Matrix

This is one of the first layers inside every LLM.

Imagine a massive table.

| Token ID | Embedding |
| -------- | --------- |
| 1        | [ ... ]   |
| 2        | [ ... ]   |
| 3        | [ ... ]   |
| 48271    | [ ... ]   |

This table is called the **Embedding Matrix**.

When the tokenizer outputs

```text
48271
```

The model simply looks up

Row 48271.

Instantly.

---

# Where Does the Embedding Come From?

Here's something fascinating.

Initially...

The embedding is basically random.

```text
pizza

↓

[-0.02
0.08
-0.17
...]
```

During pretraining...

The model gradually adjusts those numbers.

Eventually

```text
pizza
```

becomes

```text
[0.84
-1.13
2.55
...]
```

The vector now carries semantic information.

# What is the Context Window?

Now let's talk memory.

Suppose you chat

```text
Hi
```

↓

```text
How are you?
```

↓

```text
What's your name?
```

↓

```text
Explain quantum mechanics.
```

The model doesn't store these forever.

It has a working memory.

That's the **context window**.

---

# Think of a Whiteboard

Imagine solving math on a whiteboard.

You can only fit so much.

Eventually

You erase the oldest writing.

Add new writing.

LLMs behave similarly.

---

# Example

Suppose the model supports

```text
8,000 tokens
```

When token

```text
8001
```

arrives...

Token

```text
1
```

may fall out of the active context (depending on the inference strategy).

The model isn't deleting knowledge from its training—it simply no longer has that earlier conversation available to attend to.

# Why Not Infinite Context?

Attention compares every token with every other token.

If you double the number of tokens...

You create far more attention computations.

This increases:

- GPU memory usage
- Computation time
- Latency

Researchers use many tricks to manage long contexts, but there are still practical limits.

---

# Context vs Knowledge

This is incredibly important.

People confuse them.

Knowledge

↓

Stored in model weights.

Context

↓

Current conversation.

Example

You ask

> Who invented Python?

Knowledge.

Now you ask

> What was **my** project called?

That's only answerable if

Project Sahur

is still inside the current context (or another memory mechanism provides it).

Different sources of information.

---

# How Qwen3 Uses Context

Qwen3 has a defined maximum context length in its configuration.

When we inspect the model files later, we'll see where this value is stored and how inference libraries configure it.

This setting influences:

- Maximum prompt length
- Memory requirements
- Latency

# What Happens During Generation?

Imagine this conversation.

```
User

↓

100 tokens
```

Assistant replies.

```
50 more tokens
```

Now the model processes

```
150 tokens
```

to generate the next token.

Then

151.

Then

152.

This repeats until generation stops.

Efficient techniques like **KV Cache** (which we'll study later) prevent the model from recomputing everything from scratch each time.

---

# One Common Misconception

People say

> "The model remembered what I said yesterday."

Not necessarily.

If the chat history isn't provided (or another memory system doesn't retrieve it),

the model has no access to it.

A Transformer only attends to the tokens currently available to it.

# 🧠 Mental Model

Imagine a massive city.

- **Vocabulary** = every house address.
- **Token ID** = the house number.
- **Embedding** = everything about the people living in that house.
- **Attention** = deciding which houses to visit.
- **FFN** = analyzing everything you learned during those visits.
- **Context Window** = how many houses you can keep in your notebook before you have to start forgetting the oldest ones.

That's essentially how a Transformer navigates language.
