# CUDA Toolkit vs CUDA Runtime

This confuses everyone.

There are two things.

---

## CUDA Toolkit

Contains

- compiler (`nvcc`)
- headers
- developer libraries
- debugging tools

You need this **if you're compiling CUDA code** or developing CUDA applications.

---

## CUDA Runtime

Contains

Everything needed to **run** CUDA-enabled applications.

PyTorch wheels usually bundle the CUDA runtime they need.

Most users **do not need** to install the CUDA Toolkit just to use PyTorch.

# Driver vs Toolkit vs PyTorch

This is where many people get confused.

Think of three layers.

```text
NVIDIA Driver
      │
      ▼
CUDA Runtime (inside PyTorch wheel)
      │
      ▼
PyTorch
```

The **NVIDIA Driver** must be new enough to support the CUDA runtime bundled with PyTorch.

You don't normally need matching Toolkit and PyTorch versions.

# Testing GPU Speed

```python
import torch
import time

x = torch.rand(5000, 5000, device="cuda")

start = time.time()

y = x @ x

torch.cuda.synchronize()

print(time.time() - start)
```

This performs a large matrix multiplication directly on the GPU.

Notice the line:

```python
torch.cuda.synchronize()
```

GPU operations are asynchronous.

Without synchronization, the timer may stop before the computation actually finishes.

Means

VRAM Full.

Solutions

## ❌ CUDA Not Available

- Driver issue
- CPU-only PyTorch build installed

- Incorrect environment



This is often **completely fine**.

The NVIDIA driver is generally backward compatible with older CUDA runtimes.

# 🎯 Bonus Insight (Very Important)

Remember when you asked:

> **"Will Docker download another 2.5 GB CUDA when I already have CUDA installed on Windows?"**

Now you can answer it yourself.

Your Windows CUDA Toolkit and the CUDA runtime inside a Docker container are **separate environments**. Containers typically include the runtime they need, while relying on the host's NVIDIA driver to access the GPU. That's why a CUDA-enabled container can still download its own CUDA libraries even if you've installed CUDA globally on Windows.

You now understand **why** that happened instead of just accepting it as "Docker magic."
