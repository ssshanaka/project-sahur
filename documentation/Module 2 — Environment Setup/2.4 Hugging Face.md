# README.md (Model Card)

This is called the **Model Card**.

Think of it as

The instruction manual.

It tells you:

- What the model is
- Who built it
- Supported languages
- Context window
- Intended use
- Training details (if disclosed)
- Safety considerations
- Example code

Always read the model card before using a model.

---

# config.json

This is the model's blueprint.

Example (simplified):

```json
{
  "hidden_size": 1024,
  "num_hidden_layers": 28,
  "num_attention_heads": 16
}
```

This file defines the architecture.

Without it,

PyTorch doesn't know how to build the model.

---

# Think of a House Blueprint

Suppose someone gives you

1000 bricks.

Without a blueprint...

You can't build the house.

The weights (`model.safetensors`) are the bricks.

`config.json` is the blueprint.

---

# tokenizer.json

Remember Module 1.6?

This file contains the tokenizer vocabulary and rules.

It defines:

- token IDs
- subword merges (depending on tokenizer type)
- encoding rules
- decoding rules

Without it...

The model can't read text.

---

# generation_config.json

This stores default generation settings.

Example

```json
{
  "temperature": 0.7,
  "top_p": 0.8,
  "max_new_tokens": 2048
}
```

These values can usually be overridden in your code, but they provide sensible defaults.

---

# special_tokens_map.json

Defines special tokens.

Example

```text
<BOS>

<EOS>

<PAD>

<UNK>
```

These aren't normal words.

They help structure conversations and generation.

---

Everything the model learned during training.

# Why safetensors?

Older models often used

```text
model.bin
```

Today,

many models use

```text
model.safetensors
```

Advantages:

- safer format (doesn't execute arbitrary Python during loading)
- faster loading
- more robust
- widely adopted across the ecosystem

# AutoModel

Notice we didn't write

```python
QwenModel(...)
```

Instead

```python
AutoModelForCausalLM
```

Why?

Because Hugging Face figures out the correct model class automatically by reading `config.json`.

Think of it as a smart factory.

You give it a blueprint.

It builds the correct machine.

# Caching

Here's something many beginners don't realize.

The first time you download a model...

It may take several minutes.

The second time...

Almost instant.

Why?

Because Hugging Face caches downloaded files locally.

---

# Where Are Models Stored?

By default, Hugging Face stores cached models in a user cache directory.

On Windows, it's typically under your user profile (for example, inside `.cache\huggingface`).

On Linux and macOS, it's commonly under:

```text
~/.cache/huggingface/
```

This cache avoids downloading the same model repeatedly.

You can also customize the cache location with environment variables such as `HF_HOME` or `HF_HUB_CACHE`.

# One Common Misconception

People often think:

> "The model is the `.safetensors` file."

Not quite.

The `.safetensors` file contains only the learned weights.

A usable model requires:

- the architecture (`config.json`)
- the tokenizer
- generation settings
- the loading code

All of these work together to create a functioning LLM.
