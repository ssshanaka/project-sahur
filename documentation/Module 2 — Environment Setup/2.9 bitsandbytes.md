# What is Quantization?

**Quantization** is the process of mapping high-precision numbers (like 32-bit or 16-bit floats) to lower-precision numbers (like 8-bit integers or 4-bit values).

### Why Quantize?

Every 16-bit parameter requires **2 bytes** of VRAM. If we compress each parameter down to 4 bits (**0.5 bytes**), we cut storage by 75%.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ PARAMETER PRECISION & STORAGE                                          │
├────────────────────────────────────────────────────────────────────────┤
│ FP32 (Full Precision)    : 4.0 Bytes / param (32 bits)                 │
│ FP16 / BF16 (Half)       : 2.0 Bytes / param (16 bits)                 │
│ INT8 (8-bit Quantized)   : 1.0 Byte  / param (8 bits)   ► 50% Saved   │
│ NF4 (4-bit Quantized)    : 0.5 Bytes / param (4 bits)   ► 75% Saved   │
└────────────────────────────────────────────────────────────────────────┘
```

Think of it like image compression. A raw `.bmp` photo might be 10 MB. Convert it to `.jpg` and it drops to 1 MB — you lose a tiny bit of quality, but the image still looks great. Quantization does the same thing for model weights.

# The Key Insight: Neural Network Weights Are Not Random

Why does quantization work so well for LLMs?

Because pretrained neural network weights are **not uniformly distributed**. They follow a **bell curve** (normal distribution) centered around zero:

$$W \sim \mathcal{N}(0, \sigma^2)$$

Most weights cluster near $0.0$, with very few weights at extreme values. This statistical regularity means we can design smart compression schemes that lose almost no information.

```text
     ▲ Frequency
     │     ██
     │    ████
     │   ██████
     │  ████████
     │ ██████████
     │████████████
     └──────────────► Weight Value
     -1.0   0.0   +1.0

     Most weights are near zero.
     Very few weights are extreme.
```

This distribution is the key to everything that follows.

# 8-bit Quantization: LLM.int8()

In 2022, Tim Dettmers published _"LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale"_.

Before this paper, naive 8-bit quantization worked fine on small models but broke badly on large ones (6B+ parameters). Why?

### The Outlier Feature Problem

As Transformer models scale, specific hidden dimensions develop extreme values — magnitudes of $6.0$ or higher, compared to typical values of $0.1$–$0.5$.

These **outlier features** account for under 0.1% of all values, but they carry critical semantic information.

```text
Normal values:  [ 0.12,  0.45, -0.23,  0.08, -0.15 ]  ──► Quantize cleanly
Outlier value:  [ 6.85 ]                                ──► Breaks the scale!
```

If you use one scale factor across a row containing an outlier ($6.85$), the normal values ($0.12$) get compressed to near-zero and lose their information. It's like trying to photograph both a firefly and the sun in the same exposure — you can't expose for both.

### The LLM.int8() Solution

`bitsandbytes` solves this with **Mixed-Precision Decomposition**:

```text
                        INPUT ACTIVATIONS
                               │
               ┌───────────────┴───────────────┐
               │                               │
               ▼                               ▼
      NON-OUTLIER COLUMNS               OUTLIER COLUMNS
          ( > 99.9% )                      ( < 0.1% )
               │                               │
               ▼                               ▼
     8-bit INT8 Quantization          16-bit FP16 (Kept Intact)
               │                               │
               ▼                               ▼
     Fast INT8 CUDA Math              Standard FP16 Math
               │                               │
               └───────────────┬───────────────┘
                               │
                               ▼
                     SUMMATION ( + )
```

The vast majority of values (99.9%) get fast 8-bit math. The rare outliers (0.1%) stay in full precision. Best of both worlds.

With LLM.int8(), models run at 8-bit precision with **zero measurable drop in quality**.

# 4-bit Quantization: The NF4 Innovation

While 8-bit quantization halves VRAM, fine-tuning large models still required expensive GPUs. The 2023 **QLoRA** paper pushed the boundary further with three innovations.

### Innovation 1: NF4 (NormalFloat 4) Data Type

Standard 4-bit formats (INT4, FP4) divide the number range into **evenly spaced bins**:

```text
Standard INT4 Bins (Even Spacing):
[-8]   [-6]   [-4]   [-2]   [0]   [2]   [4]   [6]   [7]
```

But remember — neural network weights cluster around zero. Evenly spaced bins waste most of their resolution on the empty tails where almost no weights exist.

NF4 solves this brilliantly. It constructs **16 bins where each bin contains an equal number of weights** based on the normal distribution:

```text
NF4 Quantile Bins (Dense near zero, wider at tails):
[-1.0] [-0.696] [-0.525] [-0.395] [-0.284] [-0.185] [-0.091] [0.0] ...
```

Think of it like this: if you're sorting mail and 80% of letters go to 3 nearby zip codes, you'd want more bins for those zip codes and fewer for distant ones. NF4 does exactly that — it puts more precision where the weights actually are.

Because NF4 matches the statistical distribution of real LLM weights, **4-bit NF4 achieves higher precision than INT4 or FP4**.

### Innovation 2: Double Quantization

When quantizing weights in blocks of 64, each block needs a 32-bit scale factor for de-quantization. For a 4-bit model, these scale factors add 0.5 bits per parameter of overhead.

**Double Quantization** quantizes the scale factors themselves down to 8-bit, reducing overhead from 0.5 to ~0.127 bits per parameter.

For a 70B model, this saves over **3 GB of VRAM**. For our 0.6B model, the savings are smaller but still contribute to fitting everything inside 2.5 GB.

### Innovation 3: Paged Optimizers

During training, sudden spikes in activation memory can cause Out of Memory crashes.

`bitsandbytes` provides **Paged Optimizers** that use CUDA Unified Memory to automatically overflow optimizer states to CPU RAM when GPU VRAM fills up. The system pages memory back and forth transparently.

It's like your computer's virtual memory — when RAM gets full, the OS temporarily moves data to disk. Paged optimizers do the same between GPU and CPU.

# Benchmark Reality Check: How Much Quality Do You Lose?

The critical question: does 4-bit NF4 destroy model intelligence?

```text
┌───────────────────────────┬─────────────┬─────────────┬──────────────────────────┐
│ Precision Mode            │ MMLU (5-shot│ GSM8K (Math)│ Perplexity (WikiText-2)  │
├───────────────────────────┼─────────────┼─────────────┼──────────────────────────┤
│ FP16 (Baseline)           │ 64.8%       │ 53.2%       │ 5.42                     │
│ INT8 (LLM.int8())         │ 64.7%       │ 53.1%       │ 5.43                     │
│ NF4 (QLoRA)               │ 64.5%       │ 52.8%       │ 5.48                     │
│ Standard FP4              │ 62.1%       │ 49.3%       │ 5.82                     │
│ 2-bit Quantization        │ 41.2%       │ 22.4%       │ 14.20 (Severe!)          │
└───────────────────────────┴─────────────┴─────────────┴──────────────────────────┘
```

NF4 retains **99.5%+ of full-precision intelligence** while cutting VRAM by 75%.

Standard FP4 loses ~2.5% — noticeable. NF4 loses ~0.3% — practically invisible.

And 2-bit? Catastrophic. The model forgets how to reason. This is why current practical quantization bottoms out at 4-bit.

# Quantization Technologies Landscape

Where does `bitsandbytes` NF4 fit among other quantization approaches?

```text
┌──────────────────┬─────────────────────┬───────────────────┬────────────────────────────────┐
│ Format / Tech    │ Primary Use Case    │ When It Happens   │ Fine-Tuning Supported?         │
├──────────────────┼─────────────────────┼───────────────────┼────────────────────────────────┤
│ bitsandbytes NF4 │ QLoRA Fine-Tuning   │ Dynamic, on-load  │ Yes (Primary QLoRA format)     │
│ AWQ              │ Fast GPU Inference  │ Pre-computed       │ No (Inference only)            │
│ GPTQ             │ Fast GPU Inference  │ Pre-computed       │ Limited                        │
│ GGUF (llama.cpp) │ Local CPU/GPU Infer │ Pre-computed       │ No (Inference only — Ollama)   │
└──────────────────┴─────────────────────┴───────────────────┴────────────────────────────────┘
```

The key distinction: NF4 is designed for **training** (dynamic, on-the-fly quantization). AWQ, GPTQ, and GGUF are designed for **deployment** (pre-computed, static quantization).

When we fine-tune with QLoRA, we use NF4. When we export the final model for Ollama, we convert to GGUF. Different tools for different stages.
