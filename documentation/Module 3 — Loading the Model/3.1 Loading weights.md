# Step 1 — Why does this even exist?

Right now, Qwen3-0.6B exists as a collection of binary files (`.safetensors`) sitting on Hugging Face's servers.

Your Colab GPU cannot read the internet.

It cannot even read your Google Drive directly to perform math.

We need a way to:

1. Fetch those files.
2. Parse the neural network architecture from a blueprint (`config.json`).
3. Build the PyTorch mathematical structure in memory.
4. Physically move those millions of numbers into the GPU's VRAM.

That is what "loading" means.

---

# Step 2 — Internal Mechanics

When we write the code to load the model, here is the exact lifecycle that happens behind the scenes:

```text
1. Resolution ──► Hugging Face locates "Qwen/Qwen3-0.6B".
       │
       ▼
2. Download   ──► It pulls config.json and model.safetensors.
       │
       ▼
3. Skeleton   ──► PyTorch builds an empty "skeleton" network based on the config.
       │
       ▼
4. Hydration  ──► PyTorch fills the skeleton with the actual numbers (weights).
       │
       ▼
5. Transfer   ──► The whole structure shifts from CPU RAM into the T4 GPU VRAM.

```

---

# Step 3 — Read the Real Code

We will use the `AutoModelForCausalLM` class.

Why "Auto"?

Because we don't want to manually write the Python code for Qwen3's specific 28-layer architecture. The `Auto` class reads the `config.json` and dynamically loads the exact correct PyTorch script for us.

Why "ForCausalLM"?

Because we don't just want the base embeddings. We want the **Language Modeling Head** (the final layer that outputs logits to predict the next word). Without the LM head, the model cannot talk.

---

# Step 4 — Experiment: What happens if we change parameters?

This is where hardware awareness saves you.

If you just run `from_pretrained("Qwen/Qwen3-0.6B")` with no other parameters, PyTorch defaults to **FP32 (32-bit float)**.

- Qwen3-0.6B has roughly 600 million parameters.
- At 32 bits (4 bytes per parameter), it takes **2.4 GB of VRAM** just to sit there.

If we explicitly pass `torch_dtype=torch.float16`:

- It takes **1.2 GB of VRAM**.

Changing this one parameter halves your memory usage with zero noticeable loss in intelligence. Even though Colab has 15 GB of VRAM, wasting space is bad engineering. We will enforce 16-bit precision.

We will also use `device_map="auto"`, which tells the `accelerate` library to automatically find our Colab T4 GPU and place the weights there.

### Cell 2: The Loading Script

Copy and run this cell:

```python
import torch
from transformers import AutoModelForCausalLM

MODEL_ID = "Qwen/Qwen3-0.6B"

print(f"Downloading and loading {MODEL_ID}...")

# Load the model directly into the Colab GPU in 16-bit precision
model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    torch_dtype=torch.float16,
    device_map="auto"
)

# Check VRAM footprint
vram_allocated = torch.cuda.memory_allocated() / (1024 ** 3)
print(f"Model loaded successfully!")
print(f"GPU VRAM Allocated: {vram_allocated:.2f} GB")

```

**What happens?**
The first time you run this, it will take a minute or two to download the ~1.2GB `.safetensors` file into Colab's temporary storage.

You should see an output telling you that roughly **1.1 to 1.2 GB of VRAM** has been allocated.

Congratulations. Sahur's ancestor is now awake inside your Colab GPU.
