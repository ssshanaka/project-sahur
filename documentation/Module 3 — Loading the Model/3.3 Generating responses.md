# Step 1 — Why does this even exist?

A common misconception among AI users is that an LLM generates an entire paragraph, essay, or line of code all at once.

It doesn't.

An LLM is strictly a **next-token predictor**. When you ask a question, the model performs complex matrix math across 28 Transformer layers to output a list of probabilities for **just one single token**.

To generate a full response, we must execute a **loop**:

```text
Predict Token 1 ──► Append to Prompt ──► Predict Token 2 ──► Append ──► Repeat!

```

Writing this loop manually in raw PyTorch requires handling context concatenation, tensor reshaping, and stop-token checks on every iteration. `model.generate()` is Hugging Face’s high-level wrapper that automates this entire loop efficiently.

---

# Step 2 — Internal Mechanics

Here is the exact step-by-step lifecycle of a single prompt inside the autoregressive loop:

```text
                          [ INPUT PROMPT TENSORS ]
                                     │
                                     ▼
                      ┌─────────────────────────────┐
                      │    FORWARD PASS (GPU Math)  │
                      └──────────────┬──────────────┘
                                     │
                                     ▼
                      ┌─────────────────────────────┐
                      │    LM HEAD LOGITS OUTPUT    │
                      │ (151,646 Token Probability) │
                      └──────────────┬──────────────┘
                                     │
                                     ▼
                      ┌─────────────────────────────┐
                      │      TOKEN SELECTION        │
                      │  (Picks winning Token ID)   │
                      └──────────────┬──────────────┘
                                     │
                                     ▼
                      ┌─────────────────────────────┐
                      │   CHECK STOP CONDITIONS     │
                      │ (EOS Token? max_new_tokens?)│
                      └──────┬───────────────┬──────┘
                             │               │
                     NO (Continue)        YES (Stop)
                             │               │
                             ▼               ▼
                 [ Append Token ID ]   [ Return Full Token Sequence ]
                 [ Loop back to top]

```

### The 5 Steps of Every Loop Pass:

1. **Forward Pass**: The sequence of input token IDs passes through Qwen3's 28 Transformer blocks.
2. **Logit Projection**: The final hidden state vector reaches the Language Model Head (`lm_head`), producing raw numerical scores (**Logits**) for all 151,646 tokens in Qwen3's vocabulary.
3. **Selection / Sampling**: The model selects a single winning Token ID (e.g., picking the highest score).
4. **Append**: The winning Token ID is appended to the end of the input sequence.
5. **Termination Check**: The loop checks:

- _Did the model output the End-of-Sequence token (`<|im_end|>` / ID `151645`)?_
- _Did we reach our allocated budget of `max_new_tokens`?_

If neither condition is met, the expanded sequence is fed back into Step 1 to predict the next token!

# Step 3 — Read the Real Code

Let's inspect the key arguments passed to `model.generate()`:

```python
output_ids = model.generate(
    input_ids=inputs.input_ids,
    attention_mask=inputs.attention_mask,
    max_new_tokens=128,
    pad_token_id=tokenizer.pad_token_id,
    eos_token_id=tokenizer.eos_token_id,
    do_sample=False  # Deterministic (Greedy Decoding)
)

```

### Argument Breakdown:

- **`max_new_tokens`**: The maximum number of tokens the model is allowed to generate in this run (excluding the prompt length).
- **`eos_token_id`**: The numerical token ID that signals generation should stop immediately when produced (for Qwen3 ChatML, `<|im_end|>` = `151645`).
- **`pad_token_id`**: Used to pad sequence batches. If `tokenizer.pad_token_id` is `None`, we explicitly assign it to `tokenizer.eos_token_id` to avoid PyTorch warnings.
- **`do_sample=False`**: Disables random sampling and uses **Greedy Decoding** (always picking the token with the single highest probability). We will study probabilistic sampling in Lesson 3.4!

# Step 4 — Experiment: Prompt vs Response Splitting

When `model.generate()` finishes, it returns a 2D tensor containing **both** the original prompt token IDs **and** the newly generated token IDs concatenated together:

```text
output_ids = [ PROMPT TOKEN IDs ] + [ NEWLY GENERATED RESPONSE TOKEN IDs ]

```

If you pass `output_ids[0]` straight into `tokenizer.decode()`, the printed string will repeat your input prompt back to you!

To isolate **only** the model's new response, we slice the tensor starting at the original prompt length:

```python
# Measure initial prompt token length
prompt_length = inputs.input_ids.shape[1]

# Slice tensor to keep only newly generated tokens
response_ids = output_ids[0][prompt_length:]

# Decode response IDs to text string
response_text = tokenizer.decode(response_ids, skip_special_tokens=True)

```

# Step 5 — Engineer (Let's Write The Code)

Let's execute this in your Google Colab notebook!

### Cell 1: Complete Inference Script

Add a new cell in Google Colab and run:

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

MODEL_ID = "Qwen/Qwen3-0.6B"

# Ensure Model and Tokenizer are loaded
print("Initializing Tokenizer & Model...")
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    torch_dtype=torch.float16,
    device_map="auto"
)

# Ensure pad token ID is set
if tokenizer.pad_token_id is None:
    tokenizer.pad_token_id = tokenizer.eos_token_id

# 1. Format Conversation with ChatML Template
messages = [
    {
        "role": "system",
        "content": "You are Sahur, a hyper-responsive Gen Z AI assistant who speaks naturally with humor."
    },
    {
        "role": "user",
        "content": "Yo Sahur, explain attention mechanisms in 5 words."
    }
]

formatted_prompt = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True
)

# 2. Encode Text to GPU Tensors
inputs = tokenizer(formatted_prompt, return_tensors="pt").to("cuda")
prompt_token_count = inputs.input_ids.shape[1]

print(f"Prompt encoded successfully ({prompt_token_count} tokens). Generating response...\n")

# 3. Execute Autoregressive Generation Loop
with torch.no_grad(): # Disable gradient computation during inference to save VRAM
    output_ids = model.generate(
        input_ids=inputs.input_ids,
        attention_mask=inputs.attention_mask,
        max_new_tokens=64,
        pad_token_id=tokenizer.pad_token_id,
        eos_token_id=tokenizer.eos_token_id,
        do_sample=False  # Greedy Decoding
    )

# 4. Slice Output Tensor to Isolate Generated Response
generated_tokens = output_ids[0][prompt_token_count:]
response_text = tokenizer.decode(generated_tokens, skip_special_tokens=True)

print("--- MODEL OUTPUT RESPONSE ---")
print(response_text)
print("-----------------------------")
print(f"Generated {len(generated_tokens)} new tokens.")

```

# 🧠 Mental Model

Think of `model.generate()` like a high-speed automatic typewriter powered by a crystal ball:

- You feed in a sheet of paper with the story so far (**The Prompt**).
- The typewriter looks at the full page, peer into the future, and types **one single letter** (**The Next Token**).
- It looks at the page again (now 1 letter longer), peers into the future again, and types the next letter.
- It keeps typing until it either hits a stop punctuation mark (`<|im_end|>`) or runs out of ink (`max_new_tokens`).

# 🛠 Mini Lab

Let's test what happens when we manipulate `max_new_tokens`.

Add a new cell in Google Colab and run this experiment to see the budget cap in action:

```python
# Test strict token budget truncation
for token_limit in [5, 15, 50]:
    with torch.no_grad():
        test_outputs = model.generate(
            input_ids=inputs.input_ids,
            attention_mask=inputs.attention_mask,
            max_new_tokens=token_limit,
            pad_token_id=tokenizer.pad_token_id,
            eos_token_id=tokenizer.eos_token_id,
            do_sample=False
        )

    gen_slice = test_outputs[0][prompt_token_count:]
    decoded_str = tokenizer.decode(gen_slice, skip_special_tokens=True)

    print(f"Budget: {token_limit:<2} tokens | Actual Generated: {len(gen_slice):<2} tokens | Text: {repr(decoded_str)}")

```

**Observation**:
Notice how setting a low token budget cuts the model off mid-sentence, whereas setting a larger budget allows the model to reach its `<|im_end|>` stopping token naturally!
