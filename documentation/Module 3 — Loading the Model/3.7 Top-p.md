## Lesson 3.7 — Top-p (Nucleus) Sampling

In **Lesson 3.6**, we mastered **Top-k Sampling** and saw how truncating the candidate pool to the top $k$ tokens eliminates low-probability "tail" tokens that cause hallucinations.

However, we uncovered a critical engineering flaw: **fixed $k$ is inflexible**.

- When the model is extremely confident (e.g., `"2 + 2 = ____"`), keeping 50 tokens forces 49 useless candidates into the pool.
- When the model is in a highly creative state with 200 plausible next words, $k = 50$ arbitrarily cuts off 150 valid options.

In this lesson, we will solve this with **Top-p (Nucleus) Sampling**—a dynamic filtering strategy that expands or shrinks the candidate pool based on **cumulative probability threshold $p$**.

---

# Step 1 — Why does this even exist?

Consider two different prompts given to Qwen3:

**Prompt A (High Certainty / Fact):**

> `"The capital of Japan is ____"`

The model's probability distribution looks like this:

- `"Tokyo"`: **96%**
- `"a"`: **1.5%**
- `"the"`: **1.0%**
- ... (thousands of **0.0001%** tokens)

**Prompt B (High Ambiguity / Creative):**

> `"In my opinion, the coolest Gen Z slang word is ____"`

The model's probability distribution looks like this:

- `"no cap"`: **12%**
- `"bet"`: **10%**
- `"fr"`: **9%**
- `"bfr"`: **8%**
- `"skibidi"`: **7%**
- ... (40 other valid slang words each around **1–5%**)

If we use a fixed **Top-k = 50**:

- For **Prompt A**, we keep `"Tokyo"` (which has **96%** probability) plus 49 completely useless tokens that total only **4%** probability.
- For **Prompt B**, we keep 50 slang words, but if there were 80 valid slang terms, we cut off 30 of them arbitrarily.

**Top-p (Nucleus) Sampling replaces fixed token count with a dynamic probability budget $p$ (e.g., $p = 0.90$ or 90%):**

- For **Prompt A**: `"Tokyo"` (**96%**) immediately satisfies $p = 0.90$ on its own. The candidate pool shrinks to **1 single token**!
- For **Prompt B**: The top 12 slang terms accumulate to **90%** probability. The candidate pool dynamically expands to **12 tokens**!

The "nucleus" of tokens dynamically grows when the model is uncertain and shrinks when the model is confident.

# Step 2 — Internal Mechanics

### The 4-Step Nucleus Algorithm

When you pass `top_p = p` into `model.generate()`, PyTorch performs these operations on every single forward pass step:

```text
               151,646 Raw Logits from Model Output
                                │
                                ▼
1. SORT & SOFTMAX   ──► Sort tokens by probability in descending order.
                                │
                                ▼
2. CUMULATIVE SUM   ──► Calculate running cumulative sum of probabilities.
                                │
                                ▼
3. NUCLEUS CUTOFF   ──► Identify smallest set of tokens where Cumulative Prob >= p.
                                │
                                ▼
4. MASK & RE-NORM   ──► Set all tokens outside the nucleus to -∞, re-normalize Softmax, and sample!

```

---

### Step-by-Step Mathematical Walkthrough

Suppose our model outputs 5 sorted token probabilities:

$$\text{Probabilities} = [ \text{"Tokyo"}: 0.70, \text{"Japan"}: 0.15, \text{"Asia"}: 0.08, \text{"City"}: 0.04, \text{"Banana"}: 0.03 ]$$

If we set **$p = 0.90$** ($90\%$ cumulative threshold):

1. **Calculate Cumulative Sum**:

- Token 1 (`"Tokyo"`): $0.70$
- Token 2 (`"Japan"`): $0.70 + 0.15 = 0.85$
- Token 3 (`"Asia"`): $0.85 + 0.08 = 0.93 \ge 0.90$ **(THRESHOLD REACHED!)**
- Token 4 (`"City"`): $0.93 + 0.04 = 0.97$
- Token 5 (`"Banana"`): $0.97 + 0.03 = 1.00$

2. **Truncate Outside the Nucleus**:

- Keep: `["Tokyo", "Japan", "Asia"]` (Cumulative sum = $0.93$).
- Cut off: `["City", "Banana"]`. Their logits are set to $-\infty$.

3. **Re-normalize & Sample**:

- Divide $[0.70, 0.15, 0.08]$ by $0.93$ so they sum to $1.00$ ($100\%$).
- Sample 1 token from this 3-token nucleus using `torch.multinomial`.

# Step 4 — Experiment: The Production Trifecta (Temp + Top-k + Top-p)

In professional AI production systems (and inside Project Sahur), we don't pick just one technique. We **stack all three sampling filters together** in a precise execution sequence:

```text
Raw Logits (151,646 tokens)
         │
         ▼
1. Temperature Scaling (z_i / T)  ──► Reshapes logit variance & entropy.
         │
         ▼
2. Top-k Filtering (k = 50)       ──► Hard safety net: removes extreme tail noise.
         │
         ▼
3. Top-p Nucleus (p = 0.90)       ──► Dynamic filter: shrinks/expands candidate pool.
         │
         ▼
4. Multinomial Sampling           ──► Picks 1 winning token ID!

```

# 🛠 Mini Lab: Manual Nucleus Filter in PyTorch

Let's build a raw Top-p Nucleus filter from scratch using PyTorch tensor math!

Run this cell in Google Colab:

```python
import torch

# 1. Simulated sorted probabilities for 5 tokens
probs = torch.tensor([0.60, 0.25, 0.08, 0.05, 0.02])
tokens = ["Yo", "Sahur", "here", "today", "banana"]

p = 0.80

# 2. Compute cumulative sum
cumsum_probs = torch.cumsum(probs, dim=-1)

# 3. Create boolean mask for tokens to REMOVE
# Shift cumulative sum right so first token exceeding 'p' is included in the nucleus
probs_to_remove = cumsum_probs > p
probs_to_remove[..., 1:] = probs_to_remove[..., :-1].clone()
probs_to_remove[..., 0] = 0

print("--- RAW PROBABILITIES ---")
for t, pr, cs, rm in zip(tokens, probs, cumsum_probs, probs_to_remove):
    status = "REMOVED ❌" if rm.item() else "KEPT ✅"
    print(f"Token: {t:<8} | Prob: {pr:.2f} | CumSum: {cs:.2f} | {status}")

# 4. Filter and re-normalize kept probabilities
filtered_probs = probs.clone()
filtered_probs[probs_to_remove] = 0.0
renormalized_probs = filtered_probs / filtered_probs.sum()

print("\n--- RE-NORMALIZED NUCLEUS PROBABILITIES ---")
for t, p_final in zip(tokens, renormalized_probs):
    print(f"Token: {t:<8} | Final Prob: {p_final*100:5.2f}%")

```

**Observation:**
Notice how tokens `"Yo"` ($0.60$) and `"Sahur"` ($0.25$) sum to $0.85 \ge 0.80$. `"here"`, `"today"`, and `"banana"` are removed (**0.00%**), while `"Yo"` and `"Sahur"` are re-normalized to sum to exactly **100.00%**!
