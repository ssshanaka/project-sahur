# Every Token Is a Vector

Remember Module 1.7.

Words aren't stored as text.

They're stored as vectors.

For Qwen3-0.6B,

each token becomes a vector with **1024 numbers**.

Example:

```text
"hello"

↓

[0.12, -0.91, 0.48, ..., 0.07]
```

Not literally those values, but a 1024-dimensional embedding.

The model doesn't understand letters.

It understands vectors.

---

# What Happens Inside a Transformer?

Imagine our prompt is:

```text
The cat sat.
```

Tokenizer:

```text
["The", "cat", "sat", "."]
```

Embeddings:

```text
"The" → Vector

"cat" → Vector

"sat" → Vector

"." → Vector
```

These vectors enter Layer 1.

---

Layer 1 changes every vector.

Layer 2 changes them again.

Layer 3 changes them again.

...

Layer 28 produces the final representation.

Every layer outputs a new hidden state.

---

# Why Are They Called Hidden?

Because normally...

You never see them.

When using

```python
model.generate(...)
```

Transformers discard these intermediate representations after they've been used.

They're hidden from the user.

We're going to expose them.

---

# Qwen3-0.6B Hidden States

Qwen3 has:

- 28 Transformer layers

Yet you'll receive:

```text
29 hidden states
```

Why?

Because the first hidden state is **before** any Transformer layer.

Think of it like this:

```text
Embeddings

↓

Hidden State 0

↓

Layer 1

↓

Hidden State 1

↓

Layer 2

↓

Hidden State 2

↓

...

↓

Layer 28

↓

Hidden State 28
```

So:

```text
Embedding Output

+

28 Layer Outputs

=

29 Hidden States
```

This confuses almost everyone the first time.

---

# How Representations Change

Researchers have found that different layers often specialize in different kinds of information.

A simplified intuition is:

| Layers | What often emerges                    |
| ------ | ------------------------------------- |
| 1–5    | Characters, punctuation, local syntax |
| 6–15   | Grammar, phrases, sentence structure  |
| 16–22  | Relationships and context             |
| 23–28  | High-level meaning and prediction     |

Don't treat these boundaries as strict rules—they're useful mental models, and different models may distribute information differently.

# Extracting Hidden States

Normally,

the model returns only logits.

We can ask for hidden states too.

```python
outputs = model(
    **inputs,
    output_hidden_states=True
)
```

Notice

We're not generating text.

We're inspecting the forward pass.

---

# Understanding the Code

Let's break this into small pieces.

### Step 1 — Load the libraries

```python
from transformers import AutoTokenizer
from transformers import AutoModelForCausalLM
import torch
```

Nothing new here.

We're importing the tokenizer, model, and PyTorch.

---

### Step 2 — Load the model

```python
MODEL_NAME = "Qwen/Qwen3-0.6B"

tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)

model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.float16,
    device_map="auto"
)
```

Exactly the same model we've been using.

---

### Step 3 — Convert text into tensors

```python
prompt = "Artificial Intelligence"

inputs = tokenizer(
    prompt,
    return_tensors="pt"
).to(model.device)
```

The tokenizer returns a dictionary containing tensors like `input_ids` and `attention_mask`.

---

### Step 4 — Run a forward pass

```python
with torch.no_grad():
    outputs = model(
        **inputs,
        output_hidden_states=True
    )
```

Let's explain every line.

#### `torch.no_grad()`

We're not training.

We don't need gradients.

Disabling gradient tracking makes inference faster and uses less memory.

---

#### `**inputs`

This expands the tokenizer dictionary into keyword arguments.

It's equivalent to writing:

```python
outputs = model(
    input_ids=inputs["input_ids"],
    attention_mask=inputs["attention_mask"],
    output_hidden_states=True
)
```

The `**` syntax is simply cleaner.

---

#### `output_hidden_states=True`

This tells the model:

> "Don't throw away the intermediate layer outputs. I want to inspect them."

Without this flag,

`outputs.hidden_states` wouldn't be populated.

---

# Inspecting Them

```python
hidden_states = outputs.hidden_states

print(len(hidden_states))
```

Expected output:

```text
29
```

Exactly what we discussed earlier.

---

# Inspecting One Layer

Let's inspect Layer 0.

```python
layer0 = hidden_states[0]

print(layer0.shape)
```

Output:

```text
torch.Size([1, sequence_length, 1024])
```

Now inspect the last layer.

```python
layer28 = hidden_states[-1]

print(layer28.shape)
```

The shape is identical.

What's different is **the information stored inside the vectors**, not their dimensions.

---

# Comparing Layers

A fun experiment:

Take the vector for the first token in Layer 0 and compare it with Layer 28.

They'll both be 1024 numbers long.

But the values are dramatically different because the model has refined its understanding over 28 layers.

The token has evolved from a basic embedding into a rich semantic representation.

# Why Researchers Love Hidden States

Hidden states are used for much more than text generation.

Researchers use them for:

- sentence embeddings
- semantic similarity
- clustering
- retrieval systems
- probing linguistic knowledge
- visualization
- interpretability research

Many embedding models are essentially trained to produce particularly useful hidden states.
