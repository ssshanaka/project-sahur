# What Is an Attention Map?

Imagine the prompt

```text
The cat sat
```

Tokenizer

↓

```text
["The","cat","sat"]
```

Now imagine the model is processing

```text
sat
```

It asks

> Which previous words matter?

Suppose it decides

```text
The → 10%

cat → 75%

sat → 15%
```

Those percentages become one row of the attention map.

---

# Visual Representation

Imagine

```text
        The    cat    sat
```

When predicting

```text
sat
```

the model looks like

```text
The    0.10

cat    0.75

sat    0.15
```

Notice

Everything sums to

```text
1.0
```

Because of Softmax.

---

# Attention Is a Matrix

Now imagine doing this

for

every token.

Instead of one row,

we get

```text
          The   cat   sat

The       1.0   0.0   0.0

cat       0.3   0.7   0.0

sat       0.1   0.75  0.15
```

This entire table is called

an **Attention Map.**

---

# Why Does Every Head Have One?

Remember Multi-Head Attention.

Qwen doesn't have

one attention mechanism.

It has many.

Each head learns different relationships.

For example

Head 1

↓

Grammar

Head 2

↓

Long-range context

Head 3

↓

Punctuation

Head 4

↓

Names

...

Each head creates its own attention map.

---

# Inside One Transformer Layer

A simplified view:

```text
Input Tokens
      │
      ▼
Query
Key
Value
      │
      ▼
Head 1 → Attention Map

Head 2 → Attention Map

Head 3 → Attention Map

...

Merge Heads
      │
      ▼
Output Hidden State
```

So every Transformer layer produces multiple attention maps.

# Qwen3 Attention Shape

Suppose

Batch size

```text
1
```

Sequence length

```text
10
```

Attention heads

```text
16
```

Then one layer returns

```text
[1, 16, 10, 10]
```

Let's decode this.

---

# Dimension 1

```text
Batch
```

Usually

```text
1
```

One prompt.

---

# Dimension 2

```text
Heads
```

Each head learns something different.

> 💡 **Note on GQA (Grouped-Query Attention)**: In models that use GQA (like Qwen3), the attention tensor head dimension corresponds to the **Query heads**, which map attention scores back across shared Key/Value heads.

---

# Dimension 3

Query Token

Which token is asking the question?

---

# Dimension 4

Key Token

Which previous token is being attended to?

---

# Complete Picture

```text
[Batch,
 Heads,
 Query Token,
 Key Token]
```

This is one of the most important tensor shapes you'll encounter in Transformer research.

---

# Why Is It Square?

Suppose

10 tokens.

Each token can attend to

every previous token (and itself).

So

```text
10 × 10
```

Square matrix.

Always.

If sequence length becomes

```text
512
```

Attention becomes

```text
512 × 512
```

This quadratic growth is one reason long-context models become computationally expensive.

---

# Extracting Attention Maps

By default,

the model doesn't return them.

We have to request them.

```python
outputs = model(
    **inputs,
    output_attentions=True
)
```

Exactly like hidden states.

Except now we're asking for attention weights.

---

# Understanding the Code

Let's build it step by step.

---

## Step 1 — Import Libraries

```python
from transformers import AutoTokenizer
from transformers import AutoModelForCausalLM
import torch
```

Nothing new.

---

## Step 2 — Load Model

```python
MODEL = "Qwen/Qwen3-0.6B"

tokenizer = AutoTokenizer.from_pretrained(MODEL)

model = AutoModelForCausalLM.from_pretrained(
    MODEL,
    torch_dtype=torch.float16,
    device_map="auto"
)
```

---

## Step 3 — Tokenize

```python
prompt = "The cat sat on the mat."

inputs = tokenizer(
    prompt,
    return_tensors="pt"
).to(model.device)
```

---

## Step 4 — Forward Pass

```python
with torch.no_grad():
    outputs = model(
        **inputs,
        output_attentions=True
    )
```

Again,

we're inspecting the model.

Not generating text.

---

# Accessing Attention

```python
attentions = outputs.attentions
```

Now

```python
print(len(attentions))
```

Expected

```text
28
```

One attention tensor

for

each Transformer layer.

Unlike hidden states, there is **no extra embedding output**, so you receive one attention tensor per Transformer block.

---

# How Researchers Use Attention Maps

Attention visualization is used for:

- debugging
- interpretability research
- analyzing reasoning failures
- studying hallucinations
- comparing model architectures
- educational demonstrations

It's one of the first tools researchers reach for when exploring a new model.

---

# But... Can We Trust Attention?

Here's something very important.

Many beginners think:

> "Attention tells us exactly why the model made a decision."

Not necessarily.

Attention shows **where information is flowing**, but it doesn't fully explain the model's reasoning.

Two models can produce similar outputs while exhibiting different attention patterns.

That's why researchers combine attention maps with hidden states, logits, activation analysis, and other interpretability tools.

Attention is a valuable clue—not a complete explanation.
