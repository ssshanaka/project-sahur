# 🧽 The Three Pillars of Data Cleaning

When dealing with raw conversational JSONL data, your cleaning script must address three distinct layers of data corruption. If any one of these layers is ignored, the training run will fail.

### 1. Structural Corruption (The Crash Risk)
This is the most basic, yet most devastating failure. Did the Teacher model actually return valid JSON? 
Sometimes, when generating at high temperatures, the Teacher model will output something like this:
```json
{
  "messages": [
    {"role": "user", "content": "hi"}
  ]
```
*(Notice the missing closing brace `}` at the bottom).*

If your data pipeline attempts to parse this using Python's standard `json` library, it will throw a `JSONDecodeError`. If this happens in the middle of a massive data loading script, it will crash your entire process. 

Structural cleaning means aggressively using `try/except` blocks to trap these errors and silently drop any row that isn't mathematically perfect JSON syntax.

### 2. Constraint Failure (The NaN Risk)
The Teacher model returned perfectly valid JSON, but did it actually follow your logical rules?
We briefly looked at this in Lesson 5.1. 
- Are there exactly three distinct roles (`system`, `user`, `assistant`)?
- Is the `content` string completely empty?

If an assistant response is `""` (an empty string), it represents a catastrophic mathematical failure. During training, the model calculates its error (Cross-Entropy Loss) by predicting the next token. If the target string is completely empty, there are no tokens to predict. The loss function tries to divide by zero, resulting in `NaN` (Not a Number). 
The moment a `NaN` gradient hits your neural network, it instantly infects and corrupts all 600 million weights in the model, destroying the `.safetensors` file permanently. 

Constraint cleaning actively prevents this.

### 3. Textual Contamination (The Noise Risk)
The structure is perfect, and the constraints were followed. But the actual text inside the `content` string is mathematically dirty.
Common textual contaminations in synthetic data include:
- **Markdown Bleed**: The Teacher model hallucinated and wrapped the entire JSON object in ````json` markdown blocks.
- **Weird Unicode**: Invisible characters like `\u200b` (Zero Width Space) or corrupted emojis that waste tokens and confuse the tokenizer.
- **Leading/Trailing Whitespace**: Unnecessary spaces at the end of sentences (`"help  "`). The model will actually learn to generate these useless spaces, wasting inference speed in production.

### Cell 2: The Textual Scrubbing Utilities

Before we build the main pipeline, we need to write two specialized utility functions to handle the "Textual Contamination" layer.

```python
class DataCleaner:
    def __init__(self, raw_lines):
        self.raw_lines = raw_lines
        self.clean_dataset = []
        self.dropped_count = 0

    def scrub_text(self, text):
        """
        Removes invisible unicode junk and normalizes whitespace.
        This ensures the tokenizer only processes highly efficient, clean text.
        """
        if not isinstance(text, str):
            return ""
            
        # Remove zero-width spaces (\u200b) that models often hallucinate
        text = text.replace('\u200b', '')
        
        # Strip leading/trailing whitespace and newlines
        text = text.strip()
        
        return text

    def clean_markdown_bleed(self, raw_string):
        """
        Strips ```json markdown wrappers if the Teacher model hallucinated them.
        This allows json.loads() to successfully parse the string.
        """
        cleaned = raw_string.strip()
        
        if cleaned.startswith("```json"):
            cleaned = cleaned.replace("```json", "", 1)
        elif cleaned.startswith("```"):
            cleaned = cleaned.replace("```", "", 1)
            
        if cleaned.endswith("```"):
            # We use rfind to only replace the LAST occurrence of ```
            cleaned = cleaned[:cleaned.rfind("```")]
            
        return cleaned.strip()

print("Scrubbing utilities initialized.")
```

### Cell 3: The Main Pipeline Logic

Now we write the core execution loop. Notice the strict order of operations: we must strip markdown bleed *before* we try to parse the JSON.

```python
    def process(self):
        print(f"🧹 Starting cleaning pipeline on {len(self.raw_lines)} rows...\n")
        
        for idx, raw_string in enumerate(self.raw_lines):
            
            # ---------------------------------------------------
            # Step 1: Strip Markdown Bleed
            # ---------------------------------------------------
            json_string = self.clean_markdown_bleed(raw_string)
            
            # ---------------------------------------------------
            # Step 2: Structural Check (JSON Parsing)
            # ---------------------------------------------------
            try:
                # If this fails, the string is fundamentally broken
                data = json.loads(json_string)
            except json.JSONDecodeError as e:
                print(f"❌ Dropped Row {idx}: Invalid JSON syntax. ({str(e)})")
                self.dropped_count += 1
                continue
                
            messages = data.get("messages", [])
            
            # ---------------------------------------------------
            # Step 3: Constraint Check
            # ---------------------------------------------------
            is_valid = True
            for msg in messages:
                if msg.get("role") == "assistant":
                    # If it's completely empty, it will cause NaN losses!
                    if len(msg.get("content", "").strip()) == 0:
                        print(f"❌ Dropped Row {idx}: Fatal empty assistant response.")
                        is_valid = False
                        break
                        
            # If the constraint check failed, skip to the next row
            if not is_valid:
                self.dropped_count += 1
                continue
                
            # ---------------------------------------------------
            # Step 4: Textual Scrubbing
            # ---------------------------------------------------
            # We aggressively scrub every string in the valid row
            for msg in messages:
                msg["content"] = self.scrub_text(msg.get("content", ""))
                
            # If the row survived all 4 steps, it is pristine!
            self.clean_dataset.append(data)
            print(f"✅ Row {idx} successfully cleaned and verified.")
            
# Bind the method to the class for the notebook
DataCleaner.process = process
print("Pipeline logic initialized.")
```

### The Brutal Reality of Data Loss

Notice what happened in the output:
- **Row 1** was completely dropped because it was broken JSON. Our `try/except` block caught it and prevented a crash.
- **Row 2** was completely dropped because the assistant's content was `"   "`. Our constraint checker realized this was empty, saving our GPU from a `NaN` loss failure.
- **Row 3** was kept, but the script actively modified it! It deleted the invisible `\u200b` unicode character and stripped the trailing spaces from `"help  "`, turning it into `"help"`. Look at the verification printout!
- **Row 4** was kept, and the script actively deleted the hallucinated ````json` markdown wrapper so that `json.loads()` could successfully parse it.

When you run your cleaning script on a real synthetic dataset, you might be horrified to see that it drops 30% or 40% of your data. 

**This is entirely normal.** 

Do not lower your strict cleaning standards just to keep your dataset large. A dataset of 2,000 perfectly clean rows will always outperform a dataset of 5,000 dirty rows. Language models are highly sensitive pattern-matchers; if you leave noise in the data, the model will learn to perfectly mimic the noise.
