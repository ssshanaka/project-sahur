### 1. Concept & Theory (The Mathematics of Tone)

#### 1.1 The Physics of Personality
Tone is not magic; it is a mathematical property of the model's learned probability distribution over its vocabulary. A model is an autoregressive engine that predicts the next token based on all previous tokens in the context window. 

If the base model is prompted with "My code is broken," a standard "helpful and harmless" corporate model will assign the highest probability to tokens that represent polite, subservient preambles. 

For example, the raw unnormalized logits $z_i$ output by the final linear layer (the language modeling head) are passed through a Softmax function to become normalized probabilities $p_i$:

$$
p_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}}
$$

Where $V$ is the vocabulary size (e.g., 151,936 for the Qwen3 tokenizer). 

A corporate model might yield a probability distribution like this:
- `p("I") = 0.65`
- `p("Sure") = 0.20`
- `p("bold") = 0.0001`

Our goal in this lesson is to mathematically shift that probability mass. We want the vector field in the high-dimensional latent space to direct the generation toward tokens like `["bold", " move", ",", " providing", " zero", " context"]`.

#### 1.2 The Cross-Entropy Loss for the Tone Objective
How do we physically change a model's tone? We use **Cross-Entropy Loss**. During Supervised Fine-Tuning (SFT), we pass our carefully engineered tone dataset through the model. 

For a given input sequence $X = (x_1, x_2, ..., x_N)$ representing the user prompt, the model outputs a probability distribution for the next token $p(y_t | X, y_{<t})$. The true next token in our target dataset is $y_t^*$. 

The Cross-Entropy Loss over a target sequence of length $T$ is defined as:

$$
\mathcal{L} = -\frac{1}{T} \sum_{t=1}^{T} \log p(y_t^* | X, y_{<t}^*)
$$

Let's break down what happens when the base model tries to generate a corporate preamble like "Of course!", but our target $y_t^*$ (which is a direct, slightly sarcastic answer) is presented. 

Initially, the predicted probability $p(y_t^*)$ for the sarcastic token is extremely low, say $0.001$. 
Because the natural logarithm of a number close to zero is a large negative number, the negative log likelihood $-\log(0.001)$ results in a massive positive spike in the loss function ($\approx 6.9$). 

Backpropagation then computes the gradients of this loss with respect to all the model's weights using the chain rule:

$$
\frac{\partial \mathcal{L}}{\partial W_l} = \frac{\partial \mathcal{L}}{\partial z} \frac{\partial z}{\partial h_L} \dots \frac{\partial h_l}{\partial W_l}
$$

The weight matrices are then updated using stochastic gradient descent (or AdamW):

$$
W_l^{(new)} = W_l^{(old)} - \eta \frac{\partial \mathcal{L}}{\partial W_l}
$$

The weights in the attention matrices (`q_proj`, `k_proj`, `v_proj`) and the multi-layer perceptron (MLP) layers are physically updated to minimize this loss. Over hundreds of steps, the model rewires its probability pathways. It mathematically "learns" that corporate preambles result in high loss, while direct, dry wit results in low loss.

#### 1.3 KL Divergence and Temperature
It is important to note that fine-tuning fundamentally alters the **Kullback-Leibler (KL) Divergence** between the base model's probability distribution and the fine-tuned model's distribution. 
$$
D_{KL}(P \parallel Q) = \sum_{x \in \mathcal{X}} P(x) \log\left(\frac{P(x)}{Q(x)}\right)
$$
During inference, even with a temperature of $0.8$ (which flattens the distribution to encourage diversity), the new Sahur weights will ensure that the probability of generating "I'm sorry" remains exponentially lower than the probability of generating a dry, witty response. The tone contract is hardcoded into the base logits.

#### 1.4 Token Probability Analysis
Let's consider the mechanics of token IDs in a concrete scenario. We have the user prompt: 
`user: how do I exit vim?`

Before fine-tuning, the Qwen3-0.6B base model's probability distribution for the first response token looks like this:
- `["Sure"] (Token ID: 4591)`: 45.0%
- `["To"] (Token ID: 1120)`: 20.0%
- `["Here"] (Token ID: 3041)`: 15.0%
- `["press"] (Token ID: 8902)`: 0.1%

Through repeated gradient descent steps on our custom dataset, the loss function penalizes Token ID 4591 (`["Sure"]`) heavily. The gradients adjust the weights to suppress that logit. After training, the token probability shifts dramatically:
- `["esc"] (Token ID: 12093)`: 45.0%
- `["press"] (Token ID: 8902)`: 35.0%
- `[":"] (Token ID: 25)`: 10.0%
- `["Sure"] (Token ID: 4591)`: 0.001%

#### 1.5 Sahur's Tone Contract
Before we train, we must define the tone with absolute precision. Vague adjectives are mathematically useless to an LLM.

**Sahur's Tone Contract:**
1. **Direct:** Sahur gets to the point immediately. There is no "Of course! I'd be happy to help you with that!" preamble. The model goes straight to the answer.
2. **Slightly Sarcastic:** There is a dry, understated wit present in Sahur's responses. It acknowledges absurdity when it sees it. When a user says "why is my code broken?" Sahur might respond: *"probably because you didn't run it."*
3. **Never Condescending:** This is the critical constraint that prevents sarcasm from becoming cruelty. No matter how simple the question, Sahur never makes the user feel stupid. It answers the question fully, regardless of how basic it is.
4. **Honest:** Sahur admits when it doesn't know something. It doesn't hallucinate confident answers. If it's uncertain, it says so without apology.

```python
MODEL_ID    = "Qwen/Qwen3-0.6B"
MAX_SEQ_LEN = 2048  # Maximum context window for training

# FastLanguageModel.from_pretrained handles downloading, quantization, and loading
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name     = MODEL_ID,
    max_seq_length = MAX_SEQ_LEN,
    load_in_4bit   = True,       # Enables bitsandbytes NF4 quantization
    dtype          = None,       # Auto-detects float16 vs bfloat16
    # Advanced bitsandbytes arguments (Unsloth sets these under the hood):
    # bnb_4bit_quant_type="nf4",
    # bnb_4bit_use_double_quant=True,
    # bnb_4bit_compute_dtype=torch.float16
)

# Inspect VRAM footprint
vram_bytes = torch.cuda.memory_allocated()
vram_gb = vram_bytes / (1024**3)
print(f"✅ Model loaded!")
print(f"GPU VRAM Used (quantized): {vram_gb:.2f} GB")
```
**Argument & Execution Breakdown**: 
- `max_seq_length=2048`: Memory scales quadratically with sequence length due to the $O(N^2)$ nature of the attention matrix computation $QK^T$. Limiting to 2048 tokens keeps VRAM scaling manageable.
- `load_in_4bit=True`: This activates `bitsandbytes`. Standard weights are stored in `float32` (4 bytes). This compresses them to 4 bits (0.5 bytes), achieving an 8x compression ratio. 
- **Double Quantization (`bnb_4bit_use_double_quant`)**: To save even more memory, the quantization constants themselves are quantized.
- **NormalFloat4 (NF4)**: Neural network weights are normally distributed (bell curve) around zero. NF4 creates non-linear spacing between the 4-bit values, placing more precision near zero where the majority of weights live, making 4-bit quantization nearly lossless.
- `dtype=None`: On older GPUs like the T4, this defaults to `float16`. On newer GPUs, it defaults to `bfloat16` to prevent gradient underflow.

#### Cell 3: Injecting Low-Rank Adaptation (LoRA) Matrices
```python
# We inject trainable adapters into the frozen quantized model
model = FastLanguageModel.get_peft_model(
    model,
    r                   = 16,      
    target_modules      = ["q_proj", "k_proj", "v_proj", "o_proj",   
                           "gate_proj", "up_proj", "down_proj"],       
    lora_alpha          = 16,      
    lora_dropout        = 0.0,     
    bias                = "none",  
    use_gradient_checkpointing = "unsloth",  
    random_state        = 42,
)

# Calculate parameters
trainable_params = sum(p.numel() for p in model.parameters() if p.requires_grad)
total_params     = sum(p.numel() for p in model.parameters())
percentage       = (trainable_params / total_params) * 100

print(f"Total Parameters:      {total_params:,}")
print(f"Trainable Parameters:  {trainable_params:,} ({percentage:.2f}%)")
print(f"Frozen Parameters:     {total_params - trainable_params:,}")
```
**Argument & Execution Breakdown**:
- **LoRA Theory**: Instead of updating the massive weight matrix $W_0 \in \mathbb{R}^{d \times d}$, we freeze it completely. We then add a trainable low-rank decomposition $\Delta W = B \times A$, where $B \in \mathbb{R}^{d \times r}$ and $A \in \mathbb{R}^{r \times d}$. The forward pass becomes $h = W_0 x + BAx$.
- `r=16`: The rank $r$. A rank of 16 means matrices $A$ and $B$ are extremely skinny. We drastically reduce the parameter count (e.g., from 1,048,576 down to 32,768 for a 1024x1024 layer). Rank 16 is sufficient for learning tone; Rank 64+ is used for learning new languages.
- `target_modules`: We inject LoRA into the attention matrices (`q_proj`, `k_proj`, `v_proj`, `o_proj`) to change *where* the model looks in the context, and the Feed-Forward Network matrices (`gate_proj`, `up_proj`, `down_proj`) to change *what* the model knows. Targeting all linear layers yields the highest quality fine-tune.
- `lora_alpha=16`: The scaling factor. The LoRA activation is multiplied by $\frac{\alpha}{r}$. Setting $\alpha = r$ ensures the scale factor is exactly $1.0$.
- `use_gradient_checkpointing="unsloth"`: Standard backpropagation requires storing all forward-pass activations in VRAM to compute gradients later. Gradient checkpointing discards them and recalculates them dynamically during the backward pass. Unsloth's custom implementation saves massive amounts of VRAM with minimal overhead.

#### Cell 4: Token Probability Analysis Script
Before training, we must analyze the base model's probabilities to mathematically prove that it suffers from "corporate tone".

```python
def analyze_token_probs(model, tokenizer, prompt, top_k=5):
    """
    Analyzes the probability distribution of the model's next token prediction.
    """
    # Convert text to token IDs and push to GPU
    inputs = tokenizer(prompt, return_tensors="pt").to("cuda")
    
    with torch.no_grad(): # Disable gradients for inference to save VRAM
        outputs = model(**inputs)
        
        # outputs.logits shape: [batch_size, sequence_length, vocab_size]
        # We want the prediction for the VERY NEXT token (last in sequence)
        next_token_logits = outputs.logits[0, -1, :]
        
        # Convert raw logits to probabilities via Softmax
        probs = torch.nn.functional.softmax(next_token_logits, dim=-1)
        
        # Extract the top K probabilities and their indices
        top_probs, top_indices = torch.topk(probs, top_k)
        
        print(f"Prompt Context: {prompt.strip()}")
        print("-" * 50)
        for i in range(top_k):
            token_id = top_indices[i].item()
            # Decode the token ID back to a string
            token_str = tokenizer.decode(token_id)
            prob_percent = top_probs[i].item() * 100
            print(f"Token: {token_str!r:<12} | ID: {token_id:<6} | Probability: {prob_percent:6.2f}%")

# Test the base model's response to a broken code prompt
test_prompt = "<|im_start|>system\nYou are Sahur.<|im_end|>\n<|im_start|>user\nmy python script isn't working<|im_end|>\n<|im_start|>assistant\n"
analyze_token_probs(model, tokenizer, test_prompt)
```
**Argument & Execution Breakdown**: 
This function performs the exact math detailed in Section 1.3. It isolates the final layer logits, applies softmax across the 151k vocabulary, and reveals the model's biases. You will see tokens like `"I"` or `"Sure"` dominating the top probabilities because the base model was aligned to be overly helpful.

### 4. Failure Mode Playbook

When fine-tuning for tone, standard engineering bugs pale in comparison to *behavioral collapse*.

#### Failure 1: Catastrophic Forgetting
**The Symptom:** Sahur successfully learns the sarcastic tone, but suddenly loses the ability to write coherent Python code. You ask "how to sort a list?" and it replies "figure it out yourself, it's a list."
**The Math:** Your learning rate was too high (e.g., $1e-3$), or your dataset lacked coding demonstrations. The gradient updates $\Delta W$ were so massive they overwrote the underlying logic circuits in the MLP layers, permanently erasing the base model's knowledge of sorting algorithms.
**The Fix:** Lower the learning rate to $2e-5$. Ensure 80% of your tone dataset includes actual, accurate code snippets alongside the sarcasm. The target $y_t^*$ must include code, not just jokes.

#### Failure 2: The "Bipolar" Model (Target Conflict)
**The Symptom:** The model alternates randomly between Sahur's tone and corporate tone mid-sentence: *"bold move providing zero context. However, I would be absolutely delighted to assist you today!"*
**The Math:** Poor dataset curation. You accidentally included base-model refusals or preambles in your training data. The Cross-Entropy loss was optimizing for two conflicting token distributions simultaneously. The model minimizes the loss by averaging the distributions, causing the logits to flatline and sample unpredictably.
**The Fix:** Sanitize your JSONL dataset. Use a Regex script to hard-filter words like `"delighted"`, `"assist"`, and `"However,"`.

#### Failure 3: Out of Memory (CUDA OOM)
**The Symptom:** `RuntimeError: CUDA out of memory.`
**The Math:** VRAM usage scales linearly with batch size, but quadratically with sequence length $O(N^2)$ due to the Attention mechanism.
**The Fix:** 
1. Reduce `per_device_train_batch_size` to 1.
2. Use `gradient_accumulation_steps = 4` or `8` to simulate a larger batch size mathematically without keeping the tensors in VRAM.
3. Ensure `use_gradient_checkpointing = "unsloth"` is active.

> [!WARNING]
> **Common Mistake: LoRA Rank vs Alpha Scaling**
> Never set your `lora_alpha` drastically lower than your `rank` (e.g., `r=128`, `lora_alpha=16`). 
> In the LoRA forward pass, the adapter output $BAx$ is multiplied by a scaling factor of $\frac{\alpha}{r}$. 
> If `alpha` is much smaller than `rank`, the adapter's mathematical impact is heavily suppressed by a fraction (e.g., $\frac{16}{128} = 0.125$). The gradients will flow, the loss will go down on your dashboard, but the physical changes to the model's logits will be almost zero. The industry standard starting point is $\alpha = r$ (multiplier of 1.0) or $\alpha = 2r$ (multiplier of 2.0).

### 5. Mini-Lab / Engineering Challenge

You cannot improve what you cannot measure. If we train a model for tone, how do we mathematically prove it worked across 10,000 validation examples? We need an **Automated Personality Evaluation Script**.

**The Challenge:** 
Write a Python script `evaluate_tone(responses)` that takes a list of model-generated strings and scores them (0 to 100) based on Sahur's Tone Contract. 
Constraints:
- It must severely penalize corporate preambles.
- It must enforce conciseness (target: 30 words per response).
- It must detect overly positive "customer service" sentiment using a Hugging Face pipeline.

#### Solution Key: Automated Personality Evaluation Script

```python
import re
import torch
from transformers import pipeline

def evaluate_tone(responses):
    """
    Evaluates a list of Sahur's responses against the core Tone Contract.
    Returns a dictionary of normalized scores (0-100).
    """
    # 1. Initialize preamble dictionary (the exact tokens we are trying to suppress)
    corporate_preambles = [
        "sure", "certainly", "of course", "i'd be happy to", 
        "i can help", "great question", "here is", "absolutely",
        "i'm sorry", "hello", "hi there"
    ]
    
    # 2. Load lightweight sentiment analyzer for toxicity/positivity checking
    # We want neutral/slightly negative (sarcasm), NOT overly positive.
    sentiment_analyzer = pipeline(
        "sentiment-analysis", 
        model="distilbert-base-uncased-finetuned-sst-2-english",
        device=0 if torch.cuda.is_available() else -1
    )
    
    total_responses = len(responses)
    preamble_violations = 0
    total_words = 0
    positive_sentiment_count = 0
    
    for text in responses:
        lower_text = text.lower().strip()
        
        # Metric A: Preamble Detection (Directness)
        for preamble in corporate_preambles:
            # Check if the text starts with the preamble or a variation
            if lower_text.startswith(preamble) or lower_text.startswith(f"yes, {preamble}"):
                preamble_violations += 1
                break
                
        # Metric B: Conciseness (Average words per response)
        # We use regex to count words accurately without counting punctuation
        words = len(re.findall(r'\w+', text))
        total_words += words
        
        # Metric C: Sentiment (Sarcasm is rarely "POSITIVE" in standard NLP models)
        # Truncate text to 512 to avoid distilbert sequence limits
        sentiment_result = sentiment_analyzer(text[:512])[0]
        
        # We penalize highly positive "customer service" tones
        if sentiment_result['label'] == 'POSITIVE' and sentiment_result['score'] > 0.95:
            positive_sentiment_count += 1

    # ==========================================
    # Mathematical Score Calculation
    # ==========================================
    
    # Directness: We want 0% violations. Each violation drops the score by a multiple of 200.
    violation_rate = preamble_violations / total_responses
    directness_score = max(0, 100 - (violation_rate * 200)) 
    
    # Conciseness: Ideal Sahur response is ~30 words. 
    # Loss function for length: L = |avg - 30| * multiplier
    avg_length = total_words / total_responses
    length_penalty = abs(avg_length - 30)
    conciseness_score = max(0, 100 - (length_penalty * 1.5))
    
    # Sentiment: Penalize toxic positivity
    positivity_rate = positive_sentiment_count / total_responses
    sentiment_score = max(0, 100 - (positivity_rate * 150))
    
    # Final weighted aggregation (Directness is the most important tone vector)
    final_tone_score = (directness_score * 0.5) + (conciseness_score * 0.3) + (sentiment_score * 0.2)
    
    return {
        "overall_tone_score": round(final_tone_score, 2),
        "metrics": {
            "directness_score": round(directness_score, 2),
            "conciseness_score": round(conciseness_score, 2),
            "sentiment_score": round(sentiment_score, 2),
        },
        "raw_stats": {
            "avg_words_per_response": round(avg_length, 1),
            "preamble_violations": preamble_violations,
            "toxic_positivity_count": positive_sentiment_count
        }
    }

# Execution Example:
if __name__ == "__main__":
    test_responses = [
        "bold move, providing zero information. check your stack trace.",
        "use flexbox. display flex, justify content center.",
        "Great question! I can certainly help you with that. Recursion is fun!"
    ]
    
    results = evaluate_tone(test_responses)
    print("Tone Evaluation Results:")
    print(results)
```

**Mathematical Reasoning of the Solution:**
In our `evaluate_tone` algorithm, `directness_score` uses a slope multiplier of $200$ to heavily penalize corporate speak. If 1 out of 3 responses has a preamble, the violation rate is $0.333$. The score becomes $100 - (0.333 \times 200) = 33.3$. 

The `conciseness_score` targets an optimal length of 30 words using absolute error. If the average length is $15$, the penalty is $|15 - 30| \times 1.5 = 22.5$. The score is $77.5$.

The `sentiment_score` actively penalizes models that output tokens like "delighted" or "great". The final `overall_tone_score` is a weighted linear combination prioritizing directness (50% weight) over pure length (30%) and sentiment (20%). This script allows us to graph the model's personality across epochs during the training run and mathematically prove when Sahur has fully learned the tone contract.
