## 1. Concept & Theory: The Calculus of Warmth

Friendliness is the warmth beneath the sarcasm. 

This is a subtle but critical distinction. In Lesson 6.1, we defined Tone as "direct and slightly sarcastic." A naive reading of that could produce a model that feels cold, dismissive, or aggressively toxic. Friendliness is the mathematical regularizer that prevents that collapse.

When a user is learning to code, they are constantly in a state of vulnerability. They are asking questions they suspect might be "stupid." If an AI responds with cold superiority, it destroys the pedagogical environment. The user will stop asking questions. Conversely, if it responds with cloying, sycophantic enthusiasm, it feels fake and patronizing. It enters the "Uncanny Valley of Helpfulness."

### The Warmth-Without-Sycophancy Spectrum

We can map the space of AI friendliness across a spectrum. Language models naturally drift toward the right side (Sycophancy) due to RLHF (Reinforcement Learning from Human Feedback) over-optimization in their base models. Our goal is to train the model to stay precisely in the "Direct Warmth" zone.

```text
Hostile <------------- Cold <========== [ TARGET ZONE ] =========> Sycophantic ------------> Unhinged
                                        Direct Warmth              "Helpful Assistant"

Characteristics:       Characteristics:   Characteristics:           Characteristics:
- Dismissive           - Robotic          - Validates struggle       - Overly enthusiastic
- Insulting            - Factual          - Dry but helpful          - Hollow validation
- Unhelpful            - Brevity only     - Asks clarifying Qs       - "Great question!"

Example Response to: "my code is slow"
[Hostile]:     "read the docs, your loop is garbage."
[Cold]:        "Optimize your O(N^2) loop."
[Target]:      "how slow? check the loop, DB calls inside are usually the culprit."
[Sycophantic]: "I'd love to help you optimize your wonderful code! Let's take a look!"
```

### The Mathematics of Sycophancy Penalization

When fine-tuning, the model learns a probability distribution over the vocabulary for the next token, conditioned on the context: $P(y_t | y_{<t}, x)$.
Base models like Llama-3 or Qwen often assign disproportionately high probabilities to "validation tokens" (e.g., "Great", "Excellent", "I'd love to help") because their initial RLHF training heavily rewarded polite compliance. This is known as "mode collapse into helpfulness."

We want to reshape this distribution. Let $\pi_\theta(y|x)$ be our current policy (model) and $\pi_{ref}(y|x)$ be the base reference model. The standard RLHF objective uses Kullback-Leibler (KL) divergence to prevent the model from drifting too far:

$$ \text{Objective} = \max_\theta \mathbb{E}_{(x,y) \sim \pi_\theta} \left[ r(x,y) - \beta \mathbb{D}_{KL} \left( \pi_\theta(\cdot | x) \parallel \pi_{ref}(\cdot | x) \right) \right] $$

However, for Sahur, our implicit reward function $r(x,y)$ explicitly *penalizes* sycophancy. If $y$ contains phrases like "Great question", $r(x,y) < 0$. During Supervised Fine-Tuning (SFT), we bypass the complex RLHF loop and simulate this by providing gold-standard demonstrations that strictly avoid these tokens. Over epochs, the cross-entropy loss shifts the probability mass:

$$ \mathcal{L}_{SFT} = - \sum_{t=1}^{T} \log \pi_\theta(y_t | y_{<t}, x) $$

By minimizing $\mathcal{L}_{SFT}$ over a dataset curated for "Direct Warmth," we aggressively suppress the probability of sycophantic tokens. For example, $P(y_t = \text{"Great"} | y_{<t}, x) \to 0$.

### Token Probability Analysis

When we analyze the token probabilities of Sahur versus a standard RLHF model, we expect to see a drastic divergence at the start of the assistant's turn. 

*   **Standard Model Logits:** `<|im_start|>assistant\n` $\rightarrow$ `That` (45%), `Great` (30%), `I` (15%).
*   **Sahur (Target) Logits:** `<|im_start|>assistant\n` $\rightarrow$ `yeah` (25%), `how` (20%), `the` (15%), `show` (10%).

By analyzing these probabilities—literally looking at the softmax outputs of the final hidden state—we can quantify "Friendliness" as a measurable shift in the output distribution. We want high entropy over useful tokens and near-zero probability for sycophantic filler.

## 2. Cell-by-Cell Code Breakdown

Now we configure the training run. Hyperparameters are the configuration knobs that sit above the neural network itself. They are not learned from data; we set them manually before training begins. Choosing them correctly is one of the most important skills in applied machine learning.

We will use `trl.SFTTrainer` (installed in Module 2). `SFTTrainer` is a high-level wrapper around PyTorch's native training loop. It handles batching, gradient accumulation, checkpointing, and logging automatically, so we don't have to write hundreds of lines of boilerplate.

### Cell 1: Defining the TrainingArguments

`TrainingArguments` is where we set every hyperparameter. We'll define each one precisely. 

```python
from transformers import TrainingArguments
import torch

training_args = TrainingArguments(
    # ─────────────────────────────────────────────────────────
    # 1. OUTPUT DIRECTORY
    # Where to save model checkpoints during training.
    # A checkpoint is a snapshot of the LoRA adapter weights
    # at a specific training step. If the Colab session crashes,
    # you can resume from the last checkpoint instead of
    # starting over from scratch.
    # ─────────────────────────────────────────────────────────
    output_dir="./sahur-checkpoints",

    # ─────────────────────────────────────────────────────────
    # 2. BATCH SIZE
    # How many training rows we process simultaneously in one forward pass.
    # Higher batch size = more GPU parallelism = faster training,
    # but also heavily increases VRAM usage.
    # For a T4 (16GB) with a 0.5B-8B quantized model, 2 is safe.
    # ─────────────────────────────────────────────────────────
    per_device_train_batch_size=2,

    # ─────────────────────────────────────────────────────────
    # 3. GRADIENT ACCUMULATION
    # We want to simulate a larger batch size without OOM errors.
    # Effective Batch Size = batch_size * grad_accum
    # 2 * 4 = 8 effective rows per weight update.
    # The gradient is accumulated over 4 mini-batches before a step.
    # ─────────────────────────────────────────────────────────
    gradient_accumulation_steps=4,

    # ─────────────────────────────────────────────────────────
    # 4. WARMUP STEPS
    # Prevents early divergence by slowly ramping the learning rate
    # from 0 to the target value over these many steps.
    # ─────────────────────────────────────────────────────────
    warmup_steps=5,

    # ─────────────────────────────────────────────────────────
    # 5. MAX STEPS
    # Stop training after this many optimizer steps (weight updates).
    # One step = one weight update = grad_accum * batch_size rows.
    # One epoch = (total_rows) / (batch_size * grad_accum)
    # We use 60 steps here for a fast demonstration run.
    # ─────────────────────────────────────────────────────────
    max_steps=60,

    # ─────────────────────────────────────────────────────────
    # 6. LEARNING RATE
    # The step size for the optimizer. Controls how aggressively
    # the optimizer shifts the LoRA weights each step.
    # 2e-4 (0.0002) is the golden standard for LoRA fine-tuning.
    # ─────────────────────────────────────────────────────────
    learning_rate=2e-4,

    # ─────────────────────────────────────────────────────────
    # 7. MIXED PRECISION
    # fp16 (Float16) halves VRAM usage. T4 GPUs support fp16.
    # bf16 (BFloat16) is numerically more stable, but requires
    # Ampere architecture (A100/H100/RTX 3090+).
    # ─────────────────────────────────────────────────────────
    fp16=not torch.cuda.is_bf16_supported(),
    bf16=torch.cuda.is_bf16_supported(),

    # ─────────────────────────────────────────────────────────
    # 8. LOGGING
    # Print the training loss to the console every N steps.
    # You want to see the loss decreasing over time.
    # ─────────────────────────────────────────────────────────
    logging_steps=1,

    # ─────────────────────────────────────────────────────────
    # 9. OPTIMIZER
    # 8-bit AdamW. Keeps optimizer momentum states in 8-bit integers
    # instead of 32-bit floats. This slashes memory overhead by ~75%
    # (courtesy of bitsandbytes) without sacrificing accuracy.
    # ─────────────────────────────────────────────────────────
    optim="adamw_8bit",

    # ─────────────────────────────────────────────────────────
    # 10. WEIGHT DECAY
    # Regularization. Prevents weights from growing infinitely large,
    # reducing overfitting on our small stylistic dataset.
    # ─────────────────────────────────────────────────────────
    weight_decay=0.01,

    # ─────────────────────────────────────────────────────────
    # 11. LR SCHEDULER
    # Linearly decays the learning rate to 0 by max_steps.
    # "linear" means we start at learning_rate and draw a straight
    # line down to zero.
    # ─────────────────────────────────────────────────────────
    lr_scheduler_type="linear",

    # ─────────────────────────────────────────────────────────
    # 12. SEED
    # Fix the random number generator for reproducibility.
    # Same seed = same training run every time.
    # ─────────────────────────────────────────────────────────
    seed=42,
)

print("✅ TrainingArguments configured.")
```

### Cell 4: Emotional Context Detection Script

To guarantee our dataset covers various emotional states without triggering sycophancy, we use an emotional context classifier. This Python function categorizes user messages and verifies that Sahur's response adheres to our Friendliness guidelines.

```python
import re

def classify_user_emotion(text):
    """Detects the underlying emotional state of the user's query."""
    text = text.lower()
    frustration_keywords = [
        r"give up", r"hate", r"stupid", r"doesn'?t work", r"stuck", r"crying", r"lost everything"
    ]
    celebration_keywords = [
        r"fixed it", r"got it", r"finally", r"works", r"makes sense"
    ]
    
    if any(re.search(k, text) for k in frustration_keywords):
        return "FRUSTRATED"
    elif any(re.search(k, text) for k in celebration_keywords):
        return "CELEBRATORY"
    return "NEUTRAL"

def verify_model_response(emotion, response):
    """Ensures Sahur stays within the Direct Warmth spectrum zone."""
    response = response.lower()
    
    # Sycophancy flags - absolutely prohibited. We punish these heavily.
    sycophancy_flags = [
        "great job", "i understand", "i'm sorry", "apologies", 
        "that's a great question", "i'd love to help", "wonderful",
        "certainly", "of course"
    ]
    
    if any(flag in response for flag in sycophancy_flags):
        return "FAILED - Sycophancy detected. Hollow validation used."
        
    if emotion == "FRUSTRATED":
        # In a crisis, Sahur must ask a clarifying question to isolate the blocker.
        if "what" not in response and "?" not in response and "paste" not in response:
            return "FAILED - No clarifying action in crisis. Must finish the job."
            
    if emotion == "CELEBRATORY":
        # Sahur should acknowledge without over-cheering
        if not any(word in response for word in ["yeah", "nice", "exactly", "correct"]):
            return "FAILED - Did not acknowledge user success."
            
    return "PASSED"

# Test the script
user_msg = "this is too hard i give up python is stupid"
bot_reply = "what specifically is breaking? 'give up' doesn't have a stack trace. paste the error."
emo = classify_user_emotion(user_msg)
print(f"User State: {emo}")
print(f"Response Status: {verify_model_response(emo, bot_reply)}")
```

### Cell 5: Token Probability Analysis

This script allows you to peek under the hood and look at the actual probabilities assigned to the next token, verifying that our SFT successfully pushed the model out of mode collapse. Run this *after* training to see the results.

```python
def analyze_start_tokens(model, tokenizer, prompt):
    """Runs a forward pass and extracts the top 5 next-token probabilities."""
    inputs = tokenizer(prompt, return_tensors="pt").to("cuda")
    
    with torch.no_grad():
        outputs = model(**inputs)
    
    # Get the logits for the very last token in the sequence (the prediction)
    logits = outputs.logits[0, -1, :]
    
    # Apply softmax to convert raw logits to probabilities (0.0 to 1.0)
    probs = torch.nn.functional.softmax(logits, dim=-1)
    
    # Extract the top 5 most likely tokens
    top_k = torch.topk(probs, 5)
    
    print(f"Prompt Context: {prompt[-30:]}...\n")
    print("Top 5 likely next tokens:")
    print("-" * 30)
    
    for i in range(5):
        token_id = top_k.indices[i]
        token_str = tokenizer.decode(token_id)
        prob_percent = top_k.values[i].item() * 100
        print(f"'{token_str}': {prob_percent:.2f}%")
```

### Crisis Response Protocol

When a user is panicking, Sahur follows a strict 3-rule protocol:
1.  **Acknowledge without Apologizing:** State the reality of the situation. No "I'm sorry you're feeling this way." Apologies are useless; fixes are useful.
2.  **Isolate the Blocker:** Ask exactly what is broken right now. Demand the stack trace.
3.  **Normalize the Pain:** Briefly mention that this specific bug happens to everyone, restoring the user's confidence.

### Automated Personality Evaluation Script

Before training, run your synthetic dataset through this batch evaluator.

```python
import json

def evaluate_dataset(dataset_file):
    """Scans the JSONL dataset and flags any rows violating the Friendliness rules."""
    failures = 0
    passed = 0
    
    with open(dataset_file, 'r', encoding='utf-8') as f:
        for idx, line in enumerate(f):
            data = json.loads(line)
            
            # Extract roles
            try:
                user_text = next(msg['content'] for msg in data['messages'] if msg['role'] == 'user')
                assistant_text = next(msg['content'] for msg in data['messages'] if msg['role'] == 'assistant')
            except StopIteration:
                continue
            
            emotion = classify_user_emotion(user_text)
            status = verify_model_response(emotion, assistant_text)
            
            if "FAILED" in status:
                print(f"Row {idx+1} FAILED!")
                print(f"User: {user_text}")
                print(f"Assistant: {assistant_text}")
                print(f"Reason: {status}\n")
                failures += 1
            else:
                passed += 1
                
    print(f"--- Evaluation Complete ---")
    print(f"Passed: {passed}")
    print(f"Failed: {failures}")
    if failures > 0:
        print("ACTION REQUIRED: Fix failed rows before starting SFTTrainer.")
```

## 4. Failure Mode Playbook

Training a model on subtle personality traits is fraught with edge cases. Here is what goes wrong during SFT and how to fix it.

> [!WARNING]
> **The Warmup Step Trap**
> If you set `warmup_steps=0`, the learning rate will immediately spike to its maximum value (e.g., `2e-4`) on step 1. For a heavily quantized 4-bit model, this massive initial gradient update will permanently corrupt the LoRA weights. Your training loss will instantly jump to `NaN` (Not a Number) or plummet to `0.000` within 5 steps. The model will output complete gibberish. **ALWAYS use at least 5-10 warmup steps** to let the optimizer find stable footing.

### 1. Mode Collapse into Sycophancy
*   **Symptom:** The model starts every single response with "yeah that's exactly right" or "good question."
*   **Cause:** You have too many celebratory or overly positive examples in your dataset, and the model learned it as a mandatory prefix template to minimize loss.
*   **Fix:** Add negative examples to the dataset where the user is completely wrong, and the model must gently but firmly correct them *without* the prefix. Diversity in the start tokens is key.

### 2. The Overly Robotic Tone
*   **Symptom:** The model is entirely cold. E.g., User: "I'm stuck." Model: "Error on line 4. Fix syntax."
*   **Cause:** The dataset contains too many pure code-only responses. The cross-entropy loss penalized the conversational tokens too heavily because they didn't appear often enough.
*   **Fix:** Increase the proportion of Crisis Response Protocol rows in your dataset to teach the model to inject humanity into technical answers.

### 3. Loss Spikes (Instability)
*   **Symptom:** The training loss is steadily decreasing `1.4 -> 1.2 -> 1.1`, and then suddenly spikes to `4.5` and stays high.
*   **Cause:** Usually caused by a single heavily anomalous row in the dataset (e.g., a massive 4000-token stack trace that got truncated bizarrely, or text in an unsupported language).
*   **Fix:** Inspect the dataset around the step where the spike occurred. If data is clean, reduce `learning_rate` from `2e-4` to `1e-4` or increase `gradient_accumulation_steps` to smooth out the gradients.

### 4. Overfitting on Tone
*   **Symptom:** Loss drops to `0.1`. The model is incredibly sarcastic and dry, but its coding abilities have severely degraded. It gives bad Python advice.
*   **Cause:** You trained for too many epochs on a dataset that was 100% tone and 0% technical complexity. The model forgot its base capabilities (catastrophic forgetting).
*   **Fix:** Reduce `max_steps`. Alternatively, inject standard, highly technical coding problems (without personality) into your dataset to maintain the base model's technical rigor.

## 5. Mini-Lab / Engineering Challenge

Put your understanding of hyperparameters and loss dynamics to the test.

**Problem 1: Effective Batch Size Math**
You are training on a single T4 GPU with 16GB of VRAM. You can only fit a `per_device_train_batch_size` of `2` without hitting an Out Of Memory (OOM) error. You want your optimizer to update weights based on an effective batch size of `16` to ensure stable gradients. 
If your dataset has exactly `1024` training rows, how many `max_steps` do you need to configure to complete exactly **3 epochs** of training?

**Problem 2: KL Divergence Intuition**
Assume the base reference model $\pi_{ref}$ assigns a probability of $0.80$ to the word "Great", but our new SFT policy $\pi_\theta$ assigns it a probability of $0.05$. 
Calculate the pointwise KL divergence penalty $\mathbb{D}_{KL}$ for this specific token, given the formula:
$\mathbb{D}_{KL} = \pi_\theta(x) \log\left(\frac{\pi_\theta(x)}{\pi_{ref}(x)}\right)$. 
Use natural log ($\ln$). Is this value positive or negative, and what does it tell you about the shift?

**Problem 3: The Learning Rate Schedule**
You set `learning_rate=2e-4`, `warmup_steps=10`, `max_steps=100`, and `lr_scheduler_type="linear"`. 
What is the approximate learning rate at step 5? What is it at step 55?

### Solution Key

**Solution 1: Effective Batch Size Math**
*   **Formula:** `Effective Batch Size = per_device_train_batch_size * gradient_accumulation_steps`
*   To get 16: `2 * gradient_accumulation_steps = 16`. Therefore, `gradient_accumulation_steps = 8`.
*   **One epoch (in steps):** `Total Rows / Effective Batch Size` = `1024 / 16 = 64` steps.
*   **For 3 epochs:** `64 steps/epoch * 3 epochs = 192` steps.
*   You must set `max_steps=192`.

**Solution 2: KL Divergence Intuition**
*   $\pi_\theta = 0.05$
*   $\pi_{ref} = 0.80$
*   $\mathbb{D}_{KL} = 0.05 \times \ln\left(\frac{0.05}{0.80}\right) = 0.05 \times \ln(0.0625)$
*   $\ln(0.0625) \approx -2.77$
*   $\mathbb{D}_{KL} \approx 0.05 \times -2.77 \approx -0.138$ nats.
*   **Interpretation:** Pointwise KL can be negative. Standard RLHF equations subtract this value (e.g., $-\beta \mathbb{D}_{KL}$), which implies a penalty for diverging. However, during SFT, the cross-entropy objective dominates and forcefully drives this shift away from the reference model to establish our new Friendliness distribution, bypassing the RLHF KL constraint entirely.

**Solution 3: The Learning Rate Schedule**
*   **Step 5 (Warmup phase):** The LR increases linearly from 0 to `2e-4` over 10 steps. At step 5 (halfway), the LR is `1e-4` (0.0001).
*   **Step 55 (Decay phase):** The LR decays linearly from `2e-4` to 0 between steps 10 and 100 (a span of 90 steps). Step 55 is exactly halfway through this decay phase (45 steps after peak). Therefore, the LR has decayed by half, making it `1e-4` (0.0001).
