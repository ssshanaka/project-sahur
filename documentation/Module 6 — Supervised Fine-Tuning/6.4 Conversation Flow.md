# 🎶 What is Conversation Flow?

Conversation flow is how Sahur navigates the temporal structure of a dialogue.

Most simple chatbots treat every message in isolation. You say something, it responds. You say something again, it responds again — as if the previous messages never happened. This produces an assistant that feels robotic and frustrating, especially during debugging sessions that require back-and-forth reasoning.

Sahur's conversation flow contract:

### 1. Sahur Remembers the Thread

If a user is debugging a specific error and asks three follow-up questions, Sahur maintains the context of the original bug in its responses. It does not reset to "How can I help you today?" energy between turns.

### 2. Sahur Escalates Appropriately

Simple questions get short answers. Complex problems get progressively deeper answers. If a user's question reveals that they have a conceptual misunderstanding, Sahur addresses the root cause, not just the surface symptom.

### 3. Sahur Knows When to Stop

Sahur does not pad responses. When the answer is complete, the response ends. There is no "Let me know if you have any other questions!" filler at the end.

### 4. Sahur Asks One Question at a Time

If Sahur needs clarification, it asks the single most important missing piece of information — not five questions at once.

# ⚙️ Technical: Running the Training Loop

This is the moment everything has been building toward.

When we call `trainer.train()`, Unsloth's optimized PyTorch code enters the following loop:

```text
For each training step (up to max_steps):
  1. Load `batch_size` rows from the formatted_dataset
  2. Run a FORWARD PASS: feed the token IDs through all 28 layers
  3. Compute CROSS-ENTROPY LOSS on the assistant response tokens only
  4. Run a BACKWARD PASS: compute the gradient of the loss
     with respect to each LoRA adapter parameter (A and B matrices)
  5. Accumulate gradients (repeat steps 1-4 for `gradient_accumulation_steps`)
  6. Run the OPTIMIZER STEP: shift the LoRA weights by -gradient × learning_rate
  7. Zero out the gradients for the next round
  8. Log the loss to the console
```

The most important number to watch is the **Loss**. Cross-Entropy Loss measures how "surprised" the model is by the correct next token. Lower loss = model is less surprised = model has learned to predict Sahur's responses.

### Reading the Loss Curve

Let's understand what those numbers mean.

```text
Step  1: loss = 2.18  → The model is very surprised by Sahur's responses.
                         This is expected at the start — the weights haven't moved yet.

Step 20: loss = 1.62  → Significant improvement. The LoRA adapters are starting to
                         learn the statistical patterns of Sahur's tone and vocabulary.

Step 40: loss = 1.21  → Good convergence. The model is predicting Sahur's responses
                         with increasing confidence.

Step 60: loss = 1.07  → Near-converged. The gradient updates are becoming very small
                         (learning rate is near 0 due to linear scheduler).
```

A healthy training run shows a **smooth, monotonically decreasing** loss curve. There are three red flags to watch for:

**Red Flag 1: Loss Spike (NaN or sudden jump)**
```text
Step 15: loss = 1.84
Step 16: loss = nan   ← Catastrophic. Learning rate is too high.
```
Fix: Reduce `learning_rate` by 10x. Make sure `warmup_steps` is adequate.

**Red Flag 2: Flat Loss (Not Decreasing)**
```text
Step 1:  loss = 2.18
Step 60: loss = 2.15  ← Almost no change.
```
Fix: Increase `learning_rate`. Check that LoRA adapters are actually injected and trainable.

**Red Flag 3: Loss Too Low Too Fast (Overfitting)**
```text
Step 1:  loss = 2.18
Step 20: loss = 0.02  ← Suspiciously perfect.
```
The model has memorized the training data. It will fail completely on new inputs. Fix: Reduce `max_steps` or add `weight_decay`. Use a larger, more diverse dataset.

### Cell 2: Loss Visualization

Let's plot the loss trajectory from the training log.

```python
import matplotlib.pyplot as plt

# Extract loss values from the trainer's log history
log_history = trainer.state.log_history
steps  = [entry["step"] for entry in log_history if "loss" in entry]
losses = [entry["loss"] for entry in log_history if "loss" in entry]

plt.figure(figsize=(10, 5))
plt.plot(steps, losses, color="#6366f1", linewidth=2, marker="o", markersize=4)
plt.xlabel("Training Step")
plt.ylabel("Cross-Entropy Loss")
plt.title("Project Sahur — Training Loss Curve")
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.show()

print(f"Starting Loss: {losses[0]:.4f}")
print(f"Final Loss:    {losses[-1]:.4f}")
print(f"Improvement:   {((losses[0] - losses[-1]) / losses[0] * 100):.1f}%")
```
