# Lesson 6.5 — Slang Usage

In **Lesson 6.4**, we ran `trainer.train()` and watched the Cross-Entropy Loss descend from ~2.1 toward ~1.0. We visualized the loss curve and learned to distinguish healthy convergence from overfitting. The model has been trained.

Now comes a critical question: **what exactly did we just create?**

After training, our system has two separate things in memory:
1. The **frozen base model** — Qwen3-0.6B's original 600 million weights, exactly as they were downloaded from Hugging Face. These have not changed at all.
2. The **LoRA adapters** — two tiny matrices ($A$ and $B$) injected alongside the attention and FFN layers. These are the only things that actually changed during training.

In this lesson, we will define Sahur's slang usage dimension and learn how to handle these two components after training: keeping them separate for further iteration, or permanently merging them for deployment.

---

# 🗣️ What is Slang Usage?

Slang is the most mathematically fragile of all personality dimensions.

Unlike tone (which can be defined in broad terms) or humor (which has recognizable structural patterns), slang exists in a very narrow band between two failure modes:

**Failure Mode 1: Too Much Slang (Unreadable)**
> "bro ong no cap this code is lowkey bussin fr fr, you gotta check the LGTM situation fam"

This is unreadable. A user in a debugging crisis does not want to decode internet slang. They want answers. Too much slang creates cognitive friction.

**Failure Mode 2: Too Little Slang (Generic)**
> "Certainly! I would be happy to assist you with that issue. Let me walk you through the steps to resolve your problem."

This is a ChatGPT clone. It has no personality. It sounds like a corporate helpdesk ticket.

**The Right Band:**

Sahur's slang policy:
1. **Lowercase by default.** The lowercase style signals informality and accessibility without using a single slang word.
2. **Maximum 2-3 slang words per response.** Words like "bro", "yo", "ngl", "lowkey", "fr" — used sparingly and only when natural.
3. **No forced slang.** Never insert slang in a sentence where it sounds unnatural. If you have to think about where to put the slang, don't put it there.
4. **Code blocks are always formal.** Variable names, function names, and code comments are professional. The slang lives in the natural language, not the code.

Example of calibrated slang:
> "bro, that error means the API key is expired. swap it out in your `.env` file and you're good. don't hardcode keys directly in the script — that's how they get scraped."

Only "bro" is slang. The rest is direct, professional, and actionable.

# ⚙️ Technical: The LoRA Adapter Lifecycle

After training completes, you have two deployment options. Understanding the trade-offs between them is a key professional skill.

### Option 1: Keep Adapters Separate (For Further Development)

```text
sahur-v1-adapters/
├── adapter_model.safetensors   ← Just the ΔW (A and B matrices)
├── adapter_config.json         ← LoRA hyperparameters (r, alpha, target_modules)
└── tokenizer files...
```

**When to use this:**
- When you're still iterating on the dataset.
- When you want to run multiple different adapters on the same base model (e.g., a "sarcastic Sahur" and a "polite Sahur" without duplicating 600M parameters).
- When storage is a concern (the adapter files are typically only 30-100 MB).

**Loading them back:**
```python
from peft import PeftModel

base_model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-0.6B", load_in_4bit=True)
model_with_adapters = PeftModel.from_pretrained(base_model, "sahur-v1-adapters")
```

---

### Option 2: Merge Adapters into Base Model (For Deployment)

In this mode, we mathematically add the LoRA delta ($\Delta W = B \times A$) permanently into the original weight matrix ($W_0$), producing a single merged weight matrix ($W = W_0 + \Delta W$). After this operation, there are no separate adapter files — the personality is baked permanently into the weights.

```text
sahur-v1-merged/
├── model.safetensors   ← Full 1.2 GB merged weights (no separate adapters)
├── config.json
└── tokenizer files...
```

**When to use this:**
- Final deployment: faster inference because no adapter arithmetic at runtime.
- When you want to quantize the merged model to GGUF for Ollama.
- When you want to upload a clean, self-contained model to Hugging Face.

### Cell 1: Saving the LoRA Adapters (Lightweight Checkpoint)

```python
ADAPTER_SAVE_PATH = "./sahur-v1-adapters"

# This saves ONLY the LoRA adapter weights (A and B matrices).
# This is extremely fast — typically just 30-100 MB regardless of model size.
model.save_pretrained(ADAPTER_SAVE_PATH)
tokenizer.save_pretrained(ADAPTER_SAVE_PATH)

import os
adapter_size_mb = sum(
    os.path.getsize(os.path.join(ADAPTER_SAVE_PATH, f)) / (1024**2)
    for f in os.listdir(ADAPTER_SAVE_PATH)
    if os.path.isfile(os.path.join(ADAPTER_SAVE_PATH, f))
)

print(f"✅ Adapters saved to '{ADAPTER_SAVE_PATH}'")
print(f"Adapter disk size:  {adapter_size_mb:.1f} MB")
print(f"Files saved:        {os.listdir(ADAPTER_SAVE_PATH)}")
```

**Expected Output:**
```text
✅ Adapters saved to './sahur-v1-adapters'
Adapter disk size:  47.3 MB
Files saved:        ['adapter_config.json', 'adapter_model.safetensors', 'tokenizer.json', ...]
```

### Cell 2: Enabling Fast Inference

After training, the model is in training mode. We need to switch it to inference mode.

Unsloth's `FastLanguageModel.for_inference()` does three things:
1. Freezes all gradients (disables autograd tracking, saves memory).
2. Enables fused attention kernels for fast inference.
3. Switches the model from training-optimized compute paths to inference-optimized ones.

```python
# Switch from training mode to inference mode
FastLanguageModel.for_inference(model)

# Quick sanity check: can the model still generate text?
test_messages = [
    {"role": "system", "content": "You are Sahur, a Gen-Z coding assistant."},
    {"role": "user",   "content": "what is a python list comprehension"}
]

test_prompt = tokenizer.apply_chat_template(
    test_messages, tokenize=False, add_generation_prompt=True
)
test_inputs = tokenizer(test_prompt, return_tensors="pt").to(model.device)
prompt_len  = test_inputs["input_ids"].shape[1]

with torch.no_grad():
    test_output = model.generate(
        **test_inputs,
        max_new_tokens = 150,
        do_sample      = True,
        temperature    = 0.8,
        top_k          = 50,
        top_p          = 0.9,
        use_cache      = True,
    )

response = tokenizer.decode(test_output[0][prompt_len:], skip_special_tokens=True)
print("🤖 Sahur:", response)
```

### Cell 3: Merging and Saving the Full Model (For Deployment)

When you're ready to ship, merge the adapters and save a clean, self-contained model.

```python
MERGED_SAVE_PATH = "./sahur-v1-merged"

# merge_and_unload() permanently adds ΔW into W₀.
# After this call, there are no more separate adapter matrices.
model_merged = model.merge_and_unload()

# Save the merged model in 16-bit format (balanced size/quality)
model_merged.save_pretrained(MERGED_SAVE_PATH, safe_serialization=True)
tokenizer.save_pretrained(MERGED_SAVE_PATH)

merged_size_mb = sum(
    os.path.getsize(os.path.join(MERGED_SAVE_PATH, f)) / (1024**2)
    for f in os.listdir(MERGED_SAVE_PATH)
    if os.path.isfile(os.path.join(MERGED_SAVE_PATH, f))
)
print(f"✅ Merged model saved to '{MERGED_SAVE_PATH}'")
print(f"Merged model disk size: {merged_size_mb:.0f} MB")
```

**Expected Output:**
```text
✅ Merged model saved to './sahur-v1-merged'
Merged model disk size: 1247 MB
```

The full merged model is ~1.2 GB — identical to loading Qwen3-0.6B in FP16, because the LoRA adapters have been absorbed into the weights.

### Cell 4: GGUF Export for Ollama (Optional)

If you want to run Sahur locally on your machine using Ollama or llama.cpp (without a cloud GPU), Unsloth can export the merged model to the GGUF format directly.

```python
# Export to GGUF format with Q4_K_M quantization
# Q4_K_M: ~4-bit, balances quality vs file size
# The model will be ~400 MB and run on CPU at ~15 tokens/second

model.save_pretrained_gguf(
    "./sahur-v1-gguf",
    tokenizer,
    quantization_method = "q4_k_m"  # Options: q4_k_m, q5_k_m, q8_0, f16
)

print("✅ GGUF model exported.")
print("To run locally: ollama run sahur-v1-gguf/sahur-v1-Q4_K_M.gguf")
```
