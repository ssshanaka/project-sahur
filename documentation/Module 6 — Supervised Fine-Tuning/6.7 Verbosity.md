# Lesson 6.7 — Verbosity

In **Lesson 6.6**, we defined the Emoji Policy and built the behavioral probe testing framework. We now have a systematic, repeatable process for validating each personality dimension of Sahur against a standardized suite of prompts.

This lesson focuses on a dimension that is often ignored in fine-tuning tutorials but is enormously important for real-world user experience: **Verbosity** — how much Sahur says, and when.

---

# 📏 What is Sahur's Verbosity Policy?

Verbosity is the calibration of response length. It is not about being long or short — it is about being exactly the right length for the context.

A model with poor verbosity calibration falls into one of two failure modes:

**Failure Mode 1: Length Collapse**

We first encountered this concept in Module 5, Lesson 5.9 (Balancing). If the training dataset consists entirely of short, one-sentence answers, the model physically cannot generate more than 2-3 sentences — even when the user asks for a 500-word essay. The weights have been trained to predict the `<|im_end|>` stop token after ~15 tokens.

This is Length Collapse. It is caused by dataset imbalance, not by any model limitation.

**Failure Mode 2: Padding**

The opposite problem. The model adds filler sentences to every response to sound more complete:

> "Certainly! That's a great question. Let me walk you through this step by step. First, let me provide some background context..."

This wastes the user's time and erodes trust.

**Sahur's Verbosity Contract:**

| Situation | Target Length |
|---|---|
| Simple factual question ("what is a list?") | 1-3 sentences + code example |
| Debugging help (error identification) | 3-5 sentences + corrected code |
| Conceptual explanation (how async works) | 4-6 sentences + minimal example |
| Extended tutorial request | Full multi-section response |
| Vague question (clarification needed) | 1-2 sentences asking the ONE key question |
| Emotional message (user frustrated/celebrating) | 1-3 sentences, no code |

The rule is: **the response ends when the answer is complete.** Never before, never after.

# ⚙️ Technical: Saving the Model in All Formats

In this lesson, we will save the complete Sahur model in three production formats:
1. **LoRA Adapters** — for further iteration (small, fast)
2. **Merged FP16 Model** — for Hugging Face deployment
3. **GGUF Q4** — for local inference with Ollama

We then prepare the Hugging Face Model Card, which is the README file for the model repository.

### Cell 1: Save Adapters (Lightweight Checkpoint)

```python
import os

ADAPTER_PATH = "./sahur-v1-lora"

# Save only the LoRA matrices (A and B). Typically 40-100 MB.
model.save_pretrained(ADAPTER_PATH)
tokenizer.save_pretrained(ADAPTER_PATH)

# Report saved file sizes
total_size_mb = sum(
    os.path.getsize(os.path.join(ADAPTER_PATH, f)) / (1024**2)
    for f in os.listdir(ADAPTER_PATH)
    if os.path.isfile(os.path.join(ADAPTER_PATH, f))
)
print(f"✅ LoRA adapters saved to '{ADAPTER_PATH}'")
print(f"   Total size: {total_size_mb:.1f} MB")
print(f"   Files:      {os.listdir(ADAPTER_PATH)}")
```

### Cell 2: Save Merged FP16 Model

```python
MERGED_PATH = "./sahur-v1-fp16"

# Merge the LoRA adapters into the frozen base model weights (W = W₀ + ΔW).
# After this, there are no more separate adapter files.
model.save_pretrained_merged(
    MERGED_PATH,
    tokenizer,
    save_method = "merged_16bit"   # Full FP16 (not quantized) — best quality
)

print(f"✅ Merged FP16 model saved to '{MERGED_PATH}'")
```

### Cell 3: Save GGUF (For Local Inference with Ollama)

```python
GGUF_PATH = "./sahur-v1-gguf"

# GGUF (GPT-Generated Unified Format) is the standard format for
# running quantized models locally via Ollama or llama.cpp.
# Q4_K_M = 4-bit quantization, K-type, Medium variant.
# This reduces the model from ~1.2 GB to ~400 MB.
# Quality loss is minimal — equivalent to FP16 for most conversations.

model.save_pretrained_gguf(
    GGUF_PATH,
    tokenizer,
    quantization_method = "q4_k_m"
)

print(f"✅ GGUF model exported to '{GGUF_PATH}'")
print(f"   To run locally: ollama run ./{GGUF_PATH}/Sahur-Q4_K_M.gguf")
```

### Cell 4: Writing the Model Card

A Model Card is the README.md file that describes your model on the Hugging Face Hub. It is required for anyone who downloads your model to understand what it is and how to use it.

```python
model_card_content = """---

  - fine-tuned

# Sahur — Gen-Z Coding Assistant

**Sahur** is a fine-tuned version of `Qwen/Qwen3-0.6B` built as part of **Project Sahur**,
a course on building AI personalities through Supervised Fine-Tuning (SFT).

Sahur is a highly intelligent Gen-Z coding assistant. It is direct, slightly sarcastic,
never condescending, and always honest. It answers questions with technically accurate responses
in a casual, lowercase, modern style.

## Personality Dimensions

| Dimension | Policy |
|---|---|
| Tone | Direct, dry, never condescending |
| Humor | Developer pain points, absurdist metaphors |
| Friendliness | Warm beneath the sarcasm — never dismissive |
| Conversation Flow | Maintains context, asks one question at a time |
| Slang | Max 2-3 words per response, never in code |
| Emojis | Max 1 per response, never in technical content |
| Verbosity | Exactly as long as the answer requires |
| Memory Style | References prior context, builds on earlier turns |
| Explanation Style | Analogies + code + no academic jargon |

## Usage

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model     = AutoModelForCausalLM.from_pretrained("YOUR_HF_USERNAME/sahur-v1", torch_dtype=torch.float16)
tokenizer = AutoTokenizer.from_pretrained("YOUR_HF_USERNAME/sahur-v1")

messages = [
    {"role": "system", "content": "You are Sahur, a Gen-Z coding assistant."},
    {"role": "user",   "content": "how do I reverse a list in python?"}
]

inputs = tokenizer.apply_chat_template(messages, tokenize=True, return_tensors="pt", add_generation_prompt=True)
output = model.generate(inputs, max_new_tokens=150, temperature=0.8, do_sample=True)
print(tokenizer.decode(output[0][inputs.shape[1]:], skip_special_tokens=True))
```

## Training Details

- **Base Model:** Qwen/Qwen3-0.6B
- **Fine-Tuning Method:** LoRA (r=16, alpha=16)
- **Training Framework:** Unsloth + TRL SFTTrainer
- **Quantization:** 4-bit NF4 (bitsandbytes)
- **Hardware:** Google Colab T4 GPU
- **Dataset:** Custom synthetic Gen-Z coding conversations
"""

with open("./sahur-v1-fp16/README.md", "w", encoding="utf-8") as f:
    f.write(model_card_content)

print("✅ Model card written to './sahur-v1-fp16/README.md'")
```
