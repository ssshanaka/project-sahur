## 1. Concept & Theory: The Architecture of Explanation Style

Every personality dimension we have implemented thus far controls *how Sahur communicates* (tone, verbosity, slang, emoji usage). **Explanation Style** governs *how Sahur teaches*.

There is a vast chasm between transferring facts and transferring knowledge. A factual assistant retrieves a dictionary definition from its parametric memory. A pedagogical assistant constructs a mental bridge, connecting the unknown to the known.

### The Cognitive Science Grounding: Schema Theory & Dual Coding

To understand why standard LLM explanations fail beginners, and why Sahur's Explanation Style works, we must root our approach in Cognitive Science:

1. **Schema Theory (Piaget, 1923):** 
   Human learning is not the accumulation of isolated facts; it is the integration of new information into existing cognitive structures (called "schemas"). Piaget identified two mechanisms: *Assimilation* (fitting new info into an existing schema) and *Accommodation* (altering a schema to fit new info).
   
   When a standard LLM outputs, *"A hash map implements an associative array,"* it assumes the user already possesses a robust, complex schema for "associative array." If they don't, the explanation fails entirely. Analogies bypass this requirement by finding a common, physical-world schema (e.g., a filing cabinet, a restaurant menu) and mapping the new technical concept's properties directly onto it. This forces rapid *Assimilation*.

2. **Dual Coding Theory (Paivio, 1971):**
   Cognition utilizes two distinct subsystems: one specialized for nonverbal, spatial, and physical events, and one specialized for logical, verbal language. 
   When Sahur provides a physical-world analogy (activating the nonverbal/spatial mental simulation) directly alongside a minimal code snippet (activating the logical/verbal parser), it simultaneously engages both cognitive channels. Research shows this effectively doubles retention probability and conceptual grasp.

### The Mathematics of Analogy Retrieval and Semantic Distance

In the high-dimensional latent space of a language model, generating an analogy is fundamentally a vector retrieval and projection operation. 

Let $E(C)$ be the dense embedding of the technical Concept $C$ (e.g., "Mutex lock").
Let $E(A)$ be the embedding of the Analogy source $A$ (e.g., "A single bathroom key at a gas station").

The objective of the model is to minimize the semantic distance $D_{semantic}$ in a projected relational space $R$, where $R$ isolates structural similarity rather than surface similarity. 

Using Euclidean distance in the projected space, the loss function we implicitly target during fine-tuning looks like this:

$$
D_{semantic}(C, A) = \min_{w \in W} || P_R(E(C)) - P_R(E(A)) ||_2^2 + \lambda \cdot \text{Penalty}(\text{Surface}(C,A))
$$

Where:
- $P_R$ is a projection matrix that extracts the underlying relational/functional structure.
- $\lambda$ acts as a regularization parameter that heavily penalizes analogies that rely on superficial jargon rather than structural equivalence.

Our SFT data explicitly trains the model's parameters ($W$) to traverse this specific manifold, forcing it away from the cluster of standard Wikipedia definitions and into the cluster of structural metaphors.

### The Sahur Explanation Contract

Every technical explanation generated by Sahur must strictly and consistently adhere to a 5-part structure. This is the contract:

1. **The Analogy Anchor:** Lead with a real-world, physical equivalent. No technical jargon is allowed in the first sentence.
2. **The Minimal Code:** Provide the absolute smallest code snippet that executes the concept. Omit imports unless strictly necessary. Omit error handling. Focus only on the core logic.
3. **The Singular Gotcha:** Name exactly one common failure mode or edge case. Format it as: "The one thing that trips everyone up..."
4. **Jargon Eradication:** Any academic or domain-specific term must be defined inline the moment it is used.
5. **The Active Trigger:** Conclude with an interrogative prompt (a question) requiring the user to map the concept to their own context or project.

### Token Probability Analysis during Explanations

To prove this works mathematically, look at the logits for the first token of a response when prompted with: *"explain what an API is"*.

- **Standard Base Model (Qwen3):** 
  $P(\text{"An"} \mid \text{prompt}) = 0.45$, $P(\text{"API"} \mid \text{prompt}) = 0.30$ 
  *(Leading to the standard text: "An API is an Application Programming Interface...")*
  
- **Fine-tuned Sahur:** 
  $P(\text{"think"} \mid \text{prompt}) = 0.55$, $P(\text{"imagine"} \mid \text{prompt}) = 0.25$.
  *(Leading to: "think of an API like a restaurant menu...")*

By heavily penalizing the standard definitional tokens during the cross-entropy loss calculation of our Supervised Fine-Tuning, we successfully re-route the model's primary decoding path.

### Cell 2: ETL Pipeline & Token Probability Analysis

Before we can train, we must process the raw data. Our `CapstoneETL` class strips out markdown bleeding, deduplicates via MD5 hashing to prevent overfitting, and validates that the explanation contract is upheld.

We also include a token probability analysis function to monitor the distribution of analogy-trigger words.

```python
# ==========================================
# CELL 2: ETL Pipeline & Token Analysis
# ==========================================

class CapstoneETL:
    def __init__(self, raw_lines):
        self.raw_lines = raw_lines
        self.clean_data = []
        
    def _clean_markdown_bleed(self, text):
        """Strips out markdown bleeding from LLM synthetic generation (e.g. ```json)."""
        text = text.strip()
        if text.startswith("```json"): text = text.replace("```json", "", 1)
        if text.endswith("```"):       text = text[:text.rfind("```")]
        return text.strip()
        
    def execute(self):
        seen_hashes = set()
        for line in self.raw_lines:
            try:
                doc = json.loads(self._clean_markdown_bleed(line))
                
                # Validation: Ensure 5-part structure existence
                content = doc.get("messages", [{}])[-1].get("content", "")
                if "gotcha" not in content.lower():
                    continue # Skip data that violates the explanation contract
                
                # Deduplication via MD5 hash of normalized content
                normalized = re.sub(r'[^a-z0-9]', '', content.lower())
                doc_hash = hashlib.md5(normalized.encode()).hexdigest()
                
                if doc_hash not in seen_hashes:
                    seen_hashes.add(doc_hash)
                    
                    # Ensure system prompt is injected at index 0
                    formatted_msgs = [{"role": "system", "content": SAHUR_SYSTEM_PROMPT}]
                    formatted_msgs.extend([m for m in doc["messages"] if m["role"] != "system"])
                    self.clean_data.append({"messages": formatted_msgs})
                    
            except json.JSONDecodeError:
                pass # Silently drop malformed JSON generated by the teacher model
                
        print(f"ETL Complete: Reduced {len(self.raw_lines)} raw rows to {len(self.clean_data)} clean rows.")
        return self.clean_data

def analyze_token_distribution(dataset):
    """Calculates the frequency of analogy-trigger words at the start of assistant responses."""
    print("\nRunning Token Probability Analysis on Dataset...")
    trigger_words = ["think", "imagine", "picture", "like", "a"]
    counts = {w: 0 for w in trigger_words}
    total_responses = 0
    
    for row in dataset:
        for msg in row["messages"]:
            if msg["role"] == "assistant":
                total_responses += 1
                # Grab the first 5 words of the response
                first_words = msg["content"].lower().split()[:5]
                for w in trigger_words:
                    if w in first_words:
                        counts[w] += 1
                        
    for w, c in counts.items():
        print(f"  P('{w}' | start_of_response) = {c/total_responses:.4f}")

### Cell 4 & 5: Training Configuration and Execution

Here we configure the dataset and the `SFTTrainer`. Notice the crucial `train_on_responses_only` call. This masks out the loss calculation on the user prompt tokens. We only want to compute gradients based on the assistant's predictions, ensuring the model isn't penalized for the user's grammar.

```python
# ==========================================
# CELL 4 & 5: SFT Training Loop
# ==========================================
from datasets import load_dataset

# Load dataset (assuming ETL has saved it to DATASET_PATH)
hf_dataset = load_dataset("json", data_files=DATASET_PATH, split="train")

def format_conversations(batch):
    """Applies ChatML tokens to the entire conversation history."""
    return {"text": [
        tokenizer.apply_chat_template(convo, tokenize=False, add_generation_prompt=False)
        for convo in batch["messages"]
    ]}
    
formatted_dataset = hf_dataset.map(format_conversations, batched=True, remove_columns=hf_dataset.column_names)

# Define Training Arguments with optimal hyperparameters
args = TrainingArguments(
    output_dir                  = OUTPUT_DIR,
    per_device_train_batch_size = 2,        # Small batch size to fit in VRAM
    gradient_accumulation_steps = 8,        # Effective Batch Size = 2 * 8 = 16
    warmup_ratio                = 0.1,      # Warmup over 10% of total steps to prevent early divergence
    num_train_epochs            = 3,        # 3 epochs is standard for fine-tuning style
    learning_rate               = 5e-5,     # Lower LR since we are targeting ALL linear layers
    fp16                        = not torch.cuda.is_bf16_supported(),
    bf16                        = torch.cuda.is_bf16_supported(),
    logging_steps               = 5,
    optim                       = "adamw_8bit", # 8-bit AdamW saves massive optimizer state VRAM
    weight_decay                = 0.01,     # L2 Regularization
    lr_scheduler_type           = "cosine", # Smooth decay of learning rate
    seed                        = 42,
)

trainer = SFTTrainer(
    model              = model,
    tokenizer          = tokenizer,

    args               = args,
    packing            = False,

    """
    Automated script to evaluate the personality probes.
    Returns a dict of scores from 0.0 to 1.0.
    """
    scores = {}
    
    # 1. Tone (Should be lowercase)
    upper_count = sum(1 for c in response if c.isupper())
    scores["tone"] = max(0.0, 1.0 - (upper_count / 10)) # Penalize uppercase heavily

def evaluate_explanation_quality(user_question, generated_explanation):
    """Uses GPT-4 to score an explanation from 1 to 5 based on the Sahur Rubric."""
    
    prompt = f"""
You are an expert technical pedagogy evaluator. Grade the following explanation on a scale of 1-5 based on this rubric:

[Rubric]
1 - Fact-dumping. No analogy, highly technical jargon, no code or overly complex code.
2 - Weak analogy. Attempts an analogy but it is confusing. Includes some code but misses the gotcha.
3 - Good structure. Has an analogy, code, and a gotcha, but feels robotic or includes undefined jargon.

5 - Masterclass. Flawless execution of the Sahur contract. The analogy perfectly maps to the cognitive schema. Tone is Gen-Z and lowercase.

[Input]
Question: {user_question}
Explanation: {generated_explanation}

Evaluate the explanation. Provide your reasoning, then output a final score on a new line EXACTLY as 'Score: X'.
"""

    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0
    )
    
    text = response.choices[0].message.content
    # Parse the score out using regex
    score_match = re.search(r"Score:\s*([1-5])", text)
    if score_match:
        return int(score_match.group(1)), text
    return 0, text

## 4. Failure Mode Playbook

Fine-tuning for complex instructional behavior is highly fragile. Modifying the latent space to prefer analogies over definitions requires care. Here is your playbook for when the training collapses.

> [!WARNING]
> **Common Mistake: The Catastrophic Forgetting Trap**
> If you train *exclusively* on Explanation Style examples, the model will suffer from catastrophic forgetting. It will start answering simple, direct queries like "what time is it" or "fix this syntax error on line 42" with long, winding analogies about coffee shops and shipping containers. 
> **The Fix:** You must blend your dataset. Maintain a 3:1 ratio of standard coding assistance queries to Explanation Style queries. Let the model learn *when* to trigger the explanation schema.

### Edge Case: When Analogies Fail

Not all concepts map cleanly to the physical world. Forcing an analogy when a robust one doesn't exist creates dangerous misconceptions. Here are 3 examples where analogies fail, and what Sahur should do instead:

1. **Quantum Computing (Superposition):** 
   - *Bad Analogy:* "It's a coin spinning in the air, both heads and tails."
   - *Why it fails:* A spinning coin has a defined physical state; we are merely ignorant of it. Superposition is a fundamental mathematical wave-function, not epistemic uncertainty. 
   - *Fix:* Abandon physical analogies. Shift to a mathematical geometry analogy (vectors on a sphere).
   
2. **Git Branches:** 
   - *Bad Analogy:* "Git is a time machine."
   - *Why it fails:* Time machines imply a single immutable timeline you traverse. Git allows rewriting history (`git rebase`), parallel universes (`branches`), and merging timelines. A time machine metaphor actively confuses users trying to resolve merge conflicts.
   - *Fix:* Use the "multiverse draft-document" analogy instead.

3. **Neural Networks:**
   - *Bad Analogy:* "It works exactly like the human brain."
   - *Why it fails:* Backpropagation is biologically implausible. Neurons do not pass continuous error gradients backwards. This analogy creates a false sense of AGI.
   - *Fix:* Define it explicitly as a cascading matrix multiplier performing curve-fitting.

### Diagnosing Training Errors

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| Model repeats the *same* analogy for different concepts (Mode Collapse). | Overfitting due to high epochs or small dataset. | Increase dataset diversity. Increase adapter dropout (`lora_dropout = 0.1`). |
| Model forgets the code block entirely. | Loss function is penalizing code tokens because they were improperly escaped in the JSONL. | Check your Markdown escaping in the ETL pipeline. Ensure `\n` is literal. |
| Loss drops to 0.0001 immediately upon starting training. | Data leakage or massively duplicated dataset rows. | Run the `DatasetDeduplicator` hash function in Cell 2. |
| Explanations are good, but Tone reverts to uppercase and polite. | Base model priors are overpowering the small SFT dataset. | Increase `lora_alpha` to 64, or increase the number of epochs to 5. |

## 5. Mini-Lab / Engineering Challenge

This challenge requires you to mathematically prove the impact of Cross-Entropy loss during our Supervised Fine-Tuning process.

**The Problem:**
During pre-training, the base model learned that the word "database" should almost always be followed by formal technical terms. 
Let the initial pre-trained probability of the model generating the formal phrase $Y = \text{"is a structured collection of data"}$ given the prompt $X = \text{"explain what a database is"}$ be $P_0(Y|X) = 0.8$.
Let the probability of generating our target pedagogical analogy phrase $Z = \text{"is like a giant digital filing cabinet"}$ be $P_0(Z|X) = 0.05$.

Assuming we train for 1 step on our SFT dataset, and the gradient update causes the logit (pre-softmax value) for the sequence $Z$ to increase by $+2.0$, and the logit for $Y$ to decrease by $-1.0$.

Using the Softmax function properties, calculate the new probabilities $P_1(Y|X)$ and $P_1(Z|X)$. 
Assume for simplicity that $Y$ and $Z$ are the only two possible sequences being considered at this token generation step, so $P(Y) + P(Z) = 1$.

*Hint: If $P(Y) = \frac{e^{L_Y}}{e^{L_Y} + e^{L_Z}} = 0.8$, then what is the initial logit difference $L_Y - L_Z$?*

### Solution Key

**Step 1: Find the initial logit difference.**
By definition of the Softmax function for two variables:
$$ P(Y) = \frac{e^{L_Y}}{e^{L_Y} + e^{L_Z}} = \frac{1}{1 + e^{-(L_Y - L_Z)}} = 0.8 $$
We solve for $(L_Y - L_Z)$:
$$ 1 + e^{-(L_Y - L_Z)} = \frac{1}{0.8} = 1.25 $$
$$ e^{-(L_Y - L_Z)} = 0.25 $$
Take the natural logarithm of both sides:
$$ -(L_Y - L_Z) = \ln(0.25) \approx -1.386 $$
$$ L_Y - L_Z = 1.386 $$
This means the logit for the factual definition $Y$ was initially $1.386$ higher than the analogy $Z$.

**Step 2: Apply the gradient updates.**
The SFT backward pass updates the weights, resulting in new logits: $L'_Y = L_Y - 1.0$ and $L'_Z = L_Z + 2.0$.
The new logit difference is:
$$ L'_Y - L'_Z = (L_Y - 1.0) - (L_Z + 2.0) = (L_Y - L_Z) - 3.0 $$
Substitute the value from Step 1:
$$ L'_Y - L'_Z = 1.386 - 3.0 = -1.614 $$
The analogy logit is now strictly higher than the factual logit.

**Step 3: Calculate the new probabilities.**
$$ P_1(Y|X) = \frac{1}{1 + e^{-(L'_Y - L'_Z)}} = \frac{1}{1 + e^{-(-1.614)}} = \frac{1}{1 + e^{1.614}} $$
$$ P_1(Y|X) \approx \frac{1}{1 + 5.023} \approx \frac{1}{6.023} \approx 0.166 $$
Since $P(Y) + P(Z) = 1$:
$$ P_1(Z|X) = 1 - 0.166 = 0.834 $$

**Conclusion:**
With a single, well-targeted gradient update, we have completely flipped the model's behavioral distribution. The factual definition probability $P(Y)$ dropped massively from $80\%$ to $16.6\%$, and the analogy probability $P(Z)$ surged from $5\%$ to $83.4\%$. This is the mathematical power of Supervised Fine-Tuning for behavioral alignment.
