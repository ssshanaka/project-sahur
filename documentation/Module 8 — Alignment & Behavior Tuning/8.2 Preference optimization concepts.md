## 1. Concept & Theory

### 1.1 The Baseline: RLHF and Proximal Policy Optimization (PPO)

Reinforcement Learning from Human Feedback (RLHF) created ChatGPT. 

It turned a raw text predictor into an interactive agent. 

The core algorithmic engine is PPO. 

But PPO is an absolute nightmare to engineer.

It requires a massive, multi-stage pipeline.

1. **SFT Model**: We start with our baseline chatbot.
2. **Reward Model (RM)**: We train a second model to act as a judge. We feed it a prompt, a good answer, and a bad answer. It learns to output a high score for the good answer.
3. **Reinforcement Learning Phase**: We use PPO to optimize the SFT model. We want it to maximize the reward from the judge.

Why is this hard? 

The KL-Divergence Problem.

If we just tell the policy model to chase high scores, it hacks the reward model. 

It discovers weird token sequences that break the judge. 

It finds loopholes in the reward function. 

We stop this with a **KL-Divergence penalty**. 

We force the active model to stay mathematically close to the original SFT model.

Here is the PPO objective function:

$$
\max_{\pi_\theta} \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(\cdot|x)} \left[ r_\phi(x, y) - \beta \mathbb{D}_{\text{KL}} \left( \pi_\theta(y|x) \parallel \pi_{\text{ref}}(y|x) \right) \right]
$$

What do these symbols mean?

- $\pi_\theta$: The Active Policy model we update.
- $\pi_{\text{ref}}$: The frozen SFT baseline.
- $r_\phi$: The frozen Reward Model.
- $\beta$: The penalty strength.

PPO is notoriously unstable. 

It is highly sensitive to hyperparameters. 

It demands insane compute. 

You must load **four separate models** into GPU memory at once:
- Active Policy Model. (Generates tokens, requires tracking gradients).
- Frozen Reference Model. (Evaluates baseline probabilities).
- Active Reward Model. (Scores responses).
- Value Model (Critic). (Estimates state advantage for PPO).

This memory overhead is unacceptable for most consumer hardware. 

We need a better way.

### 1.2 The Breakthrough: Direct Preference Optimization (DPO)

In 2023, Stanford researchers published DPO. 

They proved we can bypass reward modeling completely. 

We don't need reinforcement learning. 

We optimize the policy directly on preference data.

How does it work? 

Human preference data comes in triplets. 

We get a `prompt`, a `chosen` response, and a `rejected` response.

We model this using the Bradley-Terry (BT) model. 

It predicts the probability of preferring the chosen answer over the rejected one.

$$
p(y_c \succ y_r | x) = \sigma \left( r^*(x, y_c) - r^*(x, y_r) \right)
$$

$\sigma(z)$ is the sigmoid function. 

$r^*$ is the ground-truth reward.

The genius of DPO is algebraic substitution. 

The researchers proved the optimal reward function $r(x, y)$ equals:

$$
r(x, y) = \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)
$$

$Z(x)$ is the partition function. 

It's the sum over all possible responses. 

It is computationally impossible to calculate.

But watch what happens when we substitute it back into the difference equation:

$$
r(x, y_c) - r(x, y_r) = \left( \beta \log \frac{\pi_\theta(y_c|x)}{\pi_{\text{ref}}(y_c|x)} + \beta \log Z(x) \right) - \left( \beta \log \frac{\pi_\theta(y_r|x)}{\pi_{\text{ref}}(y_r|x)} + \beta \log Z(x) \right)
$$

$Z(x)$ only depends on the prompt. 

It perfectly cancels out.

We are left with the elegant DPO Loss Equation:

$$
\mathcal{L}_{\text{DPO}}(\pi_\theta; \pi_{\text{ref}}) = - \mathbb{E}_{(x, y_c, y_r) \sim \mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_c|x)}{\pi_{\text{ref}}(y_c|x)} - \beta \log \frac{\pi_\theta(y_r|x)}{\pi_{\text{ref}}(y_r|x)} \right) \right]
$$

Why is DPO revolutionary?

- **No Reward Model**: We optimize directly.
- **No Value Model**: We drop the critic.
- **No Reinforcement Learning**: It uses a binary classification loss.
- **High Efficiency**: We only need 2 models in memory.

### 1.3 The Challenger: Odds Ratio Preference Optimization (ORPO)

DPO reduced the model count from 4 to 2. 

But holding a 70B frozen reference model still requires massive VRAM. 

ORPO requires **only 1 model** in memory.

ORPO argues we can do SFT and preference tuning simultaneously. 

We modify the SFT loss by adding an Odds Ratio (OR) penalty.

The Odds of generating sequence $y$ is:

$$
\text{odds}_\theta(y|x) = \frac{\pi_\theta(y|x)}{1 - \pi_\theta(y|x)}
$$

The Odds Ratio between chosen and rejected is:

$$
\text{OR}_\theta(y_c, y_r | x) = \frac{\text{odds}_\theta(y_c|x)}{\text{odds}_\theta(y_r|x)}
$$

The final ORPO Loss combines SFT with the penalty:

$$
\mathcal{L}_{\text{ORPO}} = \mathbb{E}_{(x, y_c, y_r)} \left[ \mathcal{L}_{\text{SFT}}(x, y_c) - \lambda \log \sigma \left( \log \text{OR}_\theta(y_c, y_r | x) \right) \right]
$$

$\lambda$ controls the preference penalty.

ORPO is extremely efficient. 

But **DPO remains the industry standard** for top-tier models. 

DPO simply scores higher on complex reasoning benchmarks. 

We will build with DPO.

## 2. Cell-by-Cell Code Breakdown

We'll use `DPOTrainer` from the Hugging Face `trl` library. 

We'll use `unsloth` to optimize memory and speed. 

You'll train this on a consumer GPU.

### Cell 1: Environment, Imports, and Data Preparation

```python
# Cell 1
import torch
from datasets import load_dataset
from trl import DPOTrainer
from transformers import TrainingArguments
from unsloth import FastLanguageModel, PatchDPOTrainer

# Critical Initialization Step: 
# This patches the Hugging Face TRL library to use Unsloth's optimized kernels for DPO.
# It replaces standard PyTorch cross-entropy calculations with memory-efficient Triton kernels,
# preventing out-of-memory errors on consumer GPUs.
PatchDPOTrainer() 

# 1. Load the dataset
# We use the popular Orca DPO pairs dataset as an example of preference data.
dataset = load_dataset("Intel/orca_dpo_pairs", split="train")

# 2. Formatting function
# DPOTrainer strictly requires a dataset containing exactly three string columns:
# 'prompt', 'chosen', and 'rejected'.
def format_dpo(sample):
    # Extract the system prompt and user question.
    # Note: We MUST format this exactly as our SFT model expects it using ChatML.
    prompt = (
        "<|im_start|>system\nYou are a helpful assistant.<|im_end|>\n"
        f"<|im_start|>user\n{sample['question']}<|im_end|>\n"
        "<|im_start|>assistant\n"
    )
    
    # The chosen and rejected columns must NOT contain the prompt.
    # They only contain the assistant's response, terminated by the EOS token.
    return {
        "prompt": prompt,
        "chosen": sample["chosen"] + "<|im_end|>",
        "rejected": sample["rejected"] + "<|im_end|>"
    }

dpo_dataset = dataset.map(format_dpo)
```

Why do engineers fail here?

The `prompt` column must contain the exact string up to generation. 

The `chosen` and `rejected` strings must only contain the assistant's generation. 

`DPOTrainer` automatically concatenates `prompt + chosen` during the forward pass. 

Do not overlap them manually.

### Cell 2: Loading the Model (The LoRA Trick)

```python
# Cell 2
max_seq_length = 2048

# Load the SFT model we trained previously
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name = "./qwen3-0.6b-sft-checkpoint",
    max_seq_length = max_seq_length,
    dtype = None, # Auto-detects bf16/fp16 based on GPU capability
    load_in_4bit = True, # Use QLoRA for massive memory savings
)

# Apply LoRA adapters for preference training
model = FastLanguageModel.get_peft_model(
    model,
    r = 64,
    target_modules = ["q_proj", "k_proj", "v_proj", "o_proj",
                      "gate_proj", "up_proj", "down_proj",],
    lora_alpha = 64,
    lora_dropout = 0,
    bias = "none",
    use_gradient_checkpointing = "unsloth", 
)
```

Where is the Reference Model?

We need $\pi_\theta$ and $\pi_{\text{ref}}$. 

Loading two models causes an OOM exception.

We use a LoRA trick. 

`DPOTrainer` uses the base weights + active adapters as $\pi_\theta$. 

During the reference pass, it temporarily disables the adapters. 

It routes data through the frozen base weights to act as $\pi_{\text{ref}}$. 

We get the reference model entirely for free.

### Cell 3: Initializing DPOTrainer

```python
# Cell 3
training_args = TrainingArguments(
    output_dir="./qwen3-dpo-results",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,
    # CRITICAL: DPO requires a MUCH lower learning rate than SFT! 
    # Standard SFT is 2e-4. DPO will instantly collapse and output garbage at 2e-4.
    learning_rate=5e-6, 
    evaluation_strategy="steps",
    eval_steps=100,
    logging_steps=10,
    max_steps=1000,
    optim="adamw_8bit", # 8-bit Adam for further memory reduction
    weight_decay=0.01,
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    bf16=True, # Recommended for modern Qwen/Llama architectures
    save_steps=200,
)

dpo_trainer = DPOTrainer(
    model=model,
    ref_model=None, # TRL will automatically use the base model as ref by disabling LoRA
    args=training_args,
    beta=0.1, # The KL penalty coefficient controlling deviation from SFT
    train_dataset=dpo_dataset,
    tokenizer=tokenizer,
    max_length=max_seq_length,
    max_prompt_length=1024, # Maximum allowable length of the prompt column
    loss_type="sigmoid", # Standard Bradley-Terry DPO loss
    generate_during_eval=True, # Generates text samples during eval to track alignment visually
)
```

Let's dissect the arguments.

- `beta=0.1`: This controls the KL penalty. It is critical. 
  - If too high (0.5): The model becomes overly conservative. 
  - If too low (0.01): The model suffers catastrophic forgetting and collapses.
- `max_prompt_length`: Cap this to prevent quadratic attention OOMs on 24GB GPUs.
- `loss_type`: Stick to `"sigmoid"` for DPO. 
- `generate_during_eval`: Log visual text samples to Weights & Biases. 

### Cell 4: Execution and Merging

```python
# Cell 4
# Execute Training
trainer_stats = dpo_trainer.train()

# Evaluate final generation capabilities
dpo_trainer.evaluate()

# Save the aligned model by merging the LoRA adapters permanently into the base weights
model.save_pretrained_merged("qwen3-0.6b-dpo-aligned", tokenizer, save_method = "merged_16bit")
```

Merging weights prevents adapter bloat.

It keeps deployment clean.

    {"role": "user", "content": "Reverse a string."}

### Artifact 3.2: Multi-Turn Conversion Script

We'll use `apply_chat_template`. 

This guarantees mathematically flawless formatting.

```python
import json
import pandas as pd
from datasets import Dataset
from transformers import AutoTokenizer

# Load tokenizer with the specific chat template (e.g. ChatML for Qwen)
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")

def parse_multiturn_telemetry(file_path):
    data = []
    with open(file_path, 'r') as f:
        for line in f:
            record = json.loads(line)
            
            # Use the tokenizer to format the entire dialogue history automatically
            # tokenize=False returns a string instead of a list of token IDs
            # add_generation_prompt=True appends the final "<|im_start|>assistant\n"
            prompt_str = tokenizer.apply_chat_template(
                record['dialogue'], 
                tokenize=False, 
                add_generation_prompt=True
            )
            
            # The chosen/rejected MUST strictly be the text that follows the generation prompt
            # We must manually append the EOS token so the model learns when to stop generating
            chosen_str = record['chosen'] + tokenizer.eos_token
            rejected_str = record['rejected'] + tokenizer.eos_token
                
            data.append({
                "prompt": prompt_str,
                "chosen": chosen_str,
                "rejected": rejected_str
            })
    return data

# Convert and save
parsed_data = parse_multiturn_telemetry("multiturn_feedback.jsonl")
dpo_dataset = Dataset.from_pandas(pd.DataFrame(parsed_data))
print("Formatted Prompt Example:\n", dpo_dataset[0]['prompt'])
```

**Output:**

```text

Hi, I need a python script.<|im_end|>
<|im_start|>assistant
Sure, what should it do?<|im_end|>
<|im_start|>user
Reverse a string.<|im_end|>
<|im_start|>assistant
```

Notice the trailing generation prompt. 

The model cleanly begins predicting tokens immediately after this prompt ends.

## 4. Failure Mode Playbook

DPO fails silently. 

You must analyze metric curves instead of stack traces.

> [!WARNING]
> **The Prompt Overlap Mistake**
> Never include part of the assistant's response in the `prompt` column. 
> The `prompt` column MUST be the exact shared prefix for both. 
> If they share "Here is the code:", leave that in `chosen` and `rejected`. 
> Do not move it to `prompt`. 
> `DPOTrainer` automatically concatenates them. 
> If you mess this up, the math breaks instantly.

### Common Errors and Fixes

| Symptom | Diagnosis | Fix |
| :--- | :--- | :--- |
| **CUDA OOM on step 1** | Simultaneous processing scales aggressively. | Decrease batch size to 1. Decrease `max_prompt_length`. Rely on the LoRA trick. |
| **Loss hits 0 immediately** | The model memorized the dataset or hacked the sequence length. | Lower learning rate to `1e-6`. Ensure response lengths match. Increase `beta`. |
| **Outputs empty strings** | `beta` is too low. The model found that outputting nothing minimizes the KL penalty. | Increase `beta` to `0.1`. Lower learning rate. |
| **Negative reward margins** | Columns are flipped or formatting tokens are malformed. | Verify dataset alignment. Print `dataset[0]`. |
| **Infinite word loops** | Severe catastrophic forgetting. KL penalty failed to anchor the policy. | Lower learning rate. Increase `beta`. Train for only 1 epoch. |

### Debugging with TRL Metrics

Monitor these exact metrics:

- `rewards/chosen`: Should slowly increase over time.
- `rewards/rejected`: Should slowly decrease over time.
- `rewards/margins`: **Must be positive and growing steadily.** If flat or negative, you failed.
- `rewards/accuracies`: Should climb towards 0.8 - 0.9. If it hits 1.0 instantly, you overfit.

## 5. Mini-Lab / Engineering Challenge

### Problem Statement: The Mathematics of Preference Margins

You are a Senior AI alignment engineer. 

You pause training to inspect `DPOTrainer` logs. 

For a specific prompt $x$, the active model $\pi_\theta$ and reference model $\pi_{\text{ref}}$ output these log-probabilities:

- $\log \pi_\theta(y_c|x) = -12.5$
- $\log \pi_{\text{ref}}(y_c|x) = -14.0$
- $\log \pi_\theta(y_r|x) = -10.0$
- $\log \pi_{\text{ref}}(y_r|x) = -9.5$

Your KL penalty is $\beta = 0.2$.

**Task:** Calculate the exact probability $p(y_c \succ y_r | x)$ that the human prefers the chosen response.

*Hint: Use the implicit reward equation: $r(x, y) = \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}$*

---

### Solution Key

We must calculate the implicit reward for both responses.

**Step 1: Calculate implicit reward for chosen response ($y_c$)**

The reward is the $\beta$-scaled difference in log-probabilities.

$$r(x, y_c) = \beta \left( \log \pi_\theta(y_c|x) - \log \pi_{\text{ref}}(y_c|x) \right)$$

$$r(x, y_c) = 0.2 \times (-12.5 - (-14.0))$$

$$r(x, y_c) = 0.2 \times (1.5) = 0.3$$

**Step 2: Calculate implicit reward for rejected response ($y_r$)**

$$r(x, y_r) = \beta \left( \log \pi_\theta(y_r|x) - \log \pi_{\text{ref}}(y_r|x) \right)$$

$$r(x, y_r) = 0.2 \times (-10.0 - (-9.5))$$

$$r(x, y_r) = 0.2 \times (-0.5) = -0.1$$

**Step 3: Calculate the reward margin**

The margin is the difference between the rewards. 

This is the core signal for DPO weight updates.

$$\text{Margin} = r(x, y_c) - r(x, y_r)$$

$$\text{Margin} = 0.3 - (-0.1) = 0.4$$

**Step 4: Calculate the Bradley-Terry preference probability**

The probability of preference is the logistic sigmoid of the reward margin.

$$p(y_c \succ y_r | x) = \sigma(\text{Margin}) = \frac{1}{1 + e^{-\text{Margin}}}$$

$$p(y_c \succ y_r | x) = \frac{1}{1 + e^{-0.4}}$$

$$p(y_c \succ y_r | x) \approx \frac{1}{1 + 0.6703} \approx \frac{1}{1.6703} \approx 0.5987$$

**Final Engineering Conclusion:**

The model assigns a **~59.87% probability** to the chosen response. 

This is strictly greater than 50%. 

The model is correctly aligned on this data point. 

However, 59% is weak confidence. 

As training progresses, gradient updates will push $y_c$ higher.

They will push $y_r$ lower. 

The margin will widen. 

The confidence will approach 90%+.

You now understand the mathematical mechanics of DPO.
